# 225 死信消息如何恢复？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

死信恢复要先分析失败原因，修复数据、配置或代码，再通过受控重放重新处理消息。
重放必须支持幂等、限速、筛选、审批、审计和结果追踪，不能把死信直接一键全量打回主队列。

恢复的目标是修复业务状态，而不是简单清空死信。

## 恢复步骤

步骤：

- 查看死信内容和失败原因。
- 判断是否仍需处理。
- 修复根因。
- 按业务键筛选消息。
- 小批量重放。
- 观察处理结果。
- 扩大重放范围。
- 标记恢复完成。

核心死信需要记录操作人和恢复依据。

## 重放风险

风险包括：

- 重复扣减。
- 重复退款。
- 重复发券。
- 大量重放压垮下游。
- 旧消息和新业务规则不兼容。
- 顺序被打乱。

因此重放前要确认消费者幂等和状态机规则。

## 工具能力

运维平台应支持：

- 按 topic 查询。
- 按业务 ID 查询。
- 按错误类型筛选。
- 单条重放。
- 批量限速重放。
- 跳过或归档。
- 操作审计。

人工直接改 MQ 风险很高。

## 在 eMall 项目中怎么讲？

如果支付成功事件进入死信，不能随便全量重放。

应先确认订单状态和支付状态，再按订单号重放，确保订单只从待支付推进到已支付一次。
