# 563 数据库连接池耗尽，如何止血？

[返回按分类学习面试题](../README.md)

## 题目

数据库连接池耗尽，如何止血？

## 先给面试官的短答案

连接池耗尽首先要限制新请求并定位连接被谁长期占用。重点检查慢 SQL、锁等待、泄漏、远程调用包在事务内和实例扩容导致的
总连接放大；盲目增大池只会把故障转移到数据库。

## 核心拆解

- 查看 active、idle、pending、获取连接耗时和连接持有时长，并关联线程栈与 Trace。
- 检查长事务、未关闭资源、锁等待、数据库网络和在 `@Transactional` 中调用下游的代码。
- 限流并关闭非核心任务，回滚问题版本；必要时终止确认安全的长查询，而不是立即重启全部实例。
- 按数据库总连接预算反推每实例池大小，补泄漏检测、事务超时和连接等待告警。

## 深度完善：生产事故 Runbook

围绕「数据库连接池耗尽，如何止血？」，事故题不要直接猜根因。高分回答要按时间线推进：先止血，再定位，再恢复，
最后补齐长期防线。面试官更看重你是否能控制影响面，而不是一次性猜中答案。
