# 447 P99 升高但平均延迟正常说明什么？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

P99 升高但平均延迟正常，说明大多数请求仍然快，但少量尾部请求变慢。问题可能来自局部热点、锁
竞争、GC、线程池排队、下游抖动、重试、缓存未命中或部分实例异常。

平均值会掩盖尾延迟，用户体验更接近 P95/P99。

## 可能原因

原因：

- 少数热点 SKU。
- 少数慢 SQL。
- 某个下游实例慢。
- GC 暂停。
- 线程池队列堆积。
- 连接池等待。
- 缓存击穿。
- 重试放大。

尾延迟通常是局部问题。

## 排查方式

方式：

- 按接口拆 P99。
- 按实例拆 P99。
- 按用户、SKU、商家拆。
- 看 Trace 慢 span。
- 看 GC 和线程池。
- 看连接池等待。
- 看下游调用分位数。

不要只看服务整体平均值。

## 业务影响

影响：

- 少量用户明显变慢。
- 支付或下单可能超时。
- 重试可能放大压力。
- SLA 可能违约。

尾延迟是高并发系统的重要指标。

## 在 eMall 项目中怎么讲？

eMall 下单接口平均 80ms，但 P99 到 3s，可能只有秒杀 SKU 的库存扣减慢。

需要按 SKU 和库存桶拆分延迟，并用 Trace 看是否卡在库存服务、数据库锁还是 Redis 令牌。
