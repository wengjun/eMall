# 206 如何做多租户或商家隔离？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

多租户隔离要防止一个商家看到、修改或拖垮另一个商家的数据和资源。
隔离要覆盖身份、权限、数据、缓存、消息、限流、配置、存储、日志和运维操作。

最低要求是所有数据访问都带租户上下文，并有强制校验和测试。

## 隔离层次

常见层次：

- 共享库共享表，通过 `tenant_id` 隔离。
- 共享库独立表。
- 独立数据库。
- 独立集群。

隔离越强，成本越高。要按商家规模、合规和风险选择。

## 必须防的问题

必须防止：

- 查询漏加 `tenant_id`。
- 缓存 key 未包含租户。
- MQ 消息没有租户上下文。
- 文件路径跨租户访问。
- 管理后台越权操作。
- 限流未按商家维度隔离。
- 日志泄露其他商家数据。

多租户系统最怕隐式上下文丢失。

## 工程措施

措施包括：

- 统一租户上下文。
- 数据访问层强制追加租户条件。
- 缓存 key 规范。
- 权限模型绑定租户。
- 按租户限流和配额。
- 审计所有跨租户操作。
- 自动化测试覆盖越权场景。

高风险商家可以使用物理隔离。

## 电商系统实践

商家后台查询商品、订单、结算单时，必须从登录身份解析 `merchantId`，并在数据访问、缓存和消息中持续传递。

运营人员跨商家操作必须有授权、审批和审计。
