# 205 运维接口为什么不能暴露公网？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

运维接口通常具备刷新配置、清缓存、重放消息、补偿订单等高权限能力，一旦暴露公网，攻击者可能直接影响生产状态。
即使有鉴权，也会增加暴力破解、凭证泄露、漏洞利用和误操作风险。

生产运维接口应放在内网、VPN、堡垒机或统一运维平台后面。

## 主要风险

风险包括：

- 未授权访问。
- 凭证被盗后直接操作生产。
- SSRF 利用访问内网接口。
- 参数注入导致批量破坏。
- 高成本操作被恶意触发。
- 敏感诊断信息泄露。
- 误操作影响大范围用户。

公网暴露会把内部管理能力变成攻击面。

## 正确隔离方式

应使用：

- 内网访问控制。
- VPN 或零信任接入。
- 堡垒机。
- 统一运维平台。
- mTLS。
- IP 白名单。
- 强认证和细粒度授权。
- 完整审计。

网络隔离不能替代鉴权，鉴权也不能替代网络隔离。

## Actuator 这类端点

Spring Actuator 端点要谨慎开放。

公网最多暴露必要健康检查，并且不包含敏感细节。环境变量、线程、堆栈、配置、日志级别修改等端点不能公网开放。

## 在 eMall 项目中怎么讲？

订单补偿、库存修复、缓存刷新、消息重放接口必须只允许运维平台在内网调用。

公网 API 网关不应路由这些接口，也不应让普通用户凭证访问。
