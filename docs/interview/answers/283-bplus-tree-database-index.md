# 283 B+Tree 为什么适合数据库索引？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

B+Tree 适合数据库索引，因为它树高低、扇出大、磁盘 IO 少，且叶子节点有序链表便于范围查询和排序扫描。
数据库索引的核心目标是减少磁盘页访问，而 B+Tree 的结构非常适合按页读取。

它比普通二叉树更适合磁盘和缓存层级。

## 扇出大

B+Tree 一个节点可以存很多 key。

好处：

- 树高低。
- 查询路径短。
- 磁盘页读取少。
- 缓存命中率高。

千万级数据通常也只需要少量层级访问。

## 范围查询友好

B+Tree 叶子节点有序连接。

适合：

- `BETWEEN`。
- `ORDER BY`。
- 范围分页。
- 按时间扫描。
- 联合索引范围过滤。

这是哈希索引不擅长的能力。

## 稳定性

B+Tree 通过分裂和合并保持平衡。

查询、插入、删除都能保持较稳定复杂度，适合数据库长期运行。

## 在 eMall 项目中怎么讲？

订单表按 `user_id, created_at` 建联合 B+Tree 索引后，可以高效查询某用户最近订单。

数据库先定位用户范围，再沿叶子节点顺序扫描最近订单记录。
