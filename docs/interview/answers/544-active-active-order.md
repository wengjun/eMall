# 544 设计异地多活订单系统。

[返回按分类学习面试题](../README.md)

## 题目

设计异地多活订单系统。

## 先给面试官的短答案

异地多活订单系统应做到区域级可用，但同一订单在任一时刻只由一个归属区域推进状态。全局幂等键、聚合版本、
路由栅栏和可审计的故障接管共同避免双写与脑裂。

## 核心拆解

- 创建订单前确定 home region，订单号携带或可查询区域信息，后续命令始终路由到该区域。
- 状态更新使用期望版本条件更新，跨区域事件按 orderId 分区并校验聚合版本。
- 接管时先隔离旧区域并提升路由 epoch，再允许新区域写入；旧 epoch 请求必须被拒绝。
- 明确接管期间暂停哪些写操作，并用订单、支付、库存对账完成恢复和安全回切。

## 深度完善：系统设计高分展开

围绕「设计异地多活订单系统。」，系统设计题要按目标、规模、架构、数据、失败路径、演进六层展开。
不要只画组件图，必须讲清每个组件为什么存在，以及它如何在大促和故障场景下保持可控。

通用的六层分析、可恢复数据模型和取舍表达集中在
[共享模型：系统设计回答框架](../shared-answer-models.md#系统设计回答框架)。本题应继续围绕上文列出的领域不变量展开，
不能机械套用通用的电商表结构和中间件清单。
