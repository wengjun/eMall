# 544 设计异地多活订单系统。

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

异地多活订单系统应做到区域级可用，但同一订单在任一时刻只由一个归属区域推进状态。全局幂等键、聚合版本、
路由栅栏和可审计的故障接管共同避免双写与脑裂。

## 核心拆解

- 创建订单前确定 home region，订单号携带或可查询区域信息，后续命令始终路由到该区域。
- 状态更新使用期望版本条件更新，跨区域事件按 orderId 分区并校验聚合版本。
- 接管时先隔离旧区域并提升路由 epoch，再允许新区域写入；旧 epoch 请求必须被拒绝。
- 明确接管期间暂停哪些写操作，并用订单、支付、库存对账完成恢复和安全回切。
