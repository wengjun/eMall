# 503 回归测试如何分层？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

回归测试应按风险和成本分层：提交阶段跑单元测试和静态检查，合并阶段跑核心集成测试，发布前跑端到端和 Smoke，
发布后跑生产 Smoke 和关键指标观察。低成本测试多跑，高成本测试少跑但覆盖核心链路。

## 分层方式

第一层是本地和提交前测试，包括单元测试、格式检查、Checkstyle、简单安全扫描和快速构建。

第二层是合并阶段测试，包括模块级集成测试、数据库迁移校验、消息序列化兼容和关键 API 契约测试。

第三层是发布前测试，包括端到端交易闭环、回归用例、性能基线和灰度前检查。

第四层是发布后测试，包括 Smoke、核心指标观察、告警检查和自动回滚条件。

## 选择用例

不是所有历史用例都要每次全跑。要根据变更影响范围选择用例，同时核心交易链路固定保留。
例如只改商品展示，可以少跑支付回调；但只要改订单状态机，就必须跑下单、支付、退款和履约相关回归。

## 电商系统实践

大型电商系统可以把 `mvn test`、模块集成测试、`smoke` 和 `loadtest` 分层放入流水线。订单、支付、库存和 Outbox 是固定核心回归，
营销、推荐和广告可以按变更影响范围选择更细的回归集。
