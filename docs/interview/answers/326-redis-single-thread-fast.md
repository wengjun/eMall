# 326 Redis 单线程为什么还能很快？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

Redis 快不是因为单线程本身快，而是因为大多数操作在内存中完成，数据结构高效，命令执行简单，
并且使用 IO 多路复用处理大量连接，避免了频繁线程切换和锁竞争。

需要补充的是，现代 Redis 在网络 IO、持久化和异步任务上并不完全是单线程。

## 快的原因

主要原因：

- 内存访问速度快。
- 数据结构针对常见操作优化。
- 单线程命令执行避免锁竞争。
- IO 多路复用减少阻塞。
- 协议简单。
- 大多数命令时间复杂度较低。

这些因素叠加后，Redis 对短小命令非常高效。

## 单线程的边界

单线程不代表没有风险。

风险包括：

- 慢命令阻塞后续请求。
- 大 key 删除阻塞主线程。
- 复杂 Lua 脚本阻塞主线程。
- 高流量热 key 打满单核。
- 持久化和复制压力影响延迟。

所以 Redis 快的前提是命令短、小、可控。

## 生产优化

常见做法：

- 禁止线上使用高风险命令。
- 控制 value 大小。
- 拆分大 key。
- 监控慢命令。
- 热 key 分散。
- 使用 Pipeline 降低网络往返。
- 用 Cluster 扩展容量和吞吐。

Redis 要按单核瓶颈做容量评估。

## 在 eMall 项目中怎么讲？

eMall 的商品详情缓存适合 Redis，因为读取是短小的内存访问。

但是购物车 Hash 如果某个用户字段过多，或者热销榜 ZSet 过大，就可能形成慢命令和大 key。
因此项目中要限制 key 大小，并对热 key 做拆分和本地缓存。
