# 147 Spring 如何处理 Bean 循环依赖？

[返回按分类学习面试题](../README.md)

## 只补容器实现差异

构造函数环 `A(B) -> B(A)` 无法靠提前暴露“构造完成的 A”解决，因为 A 还没有构造出来。
某些单例 Setter/字段注入环可以在允许循环引用时借助早期引用处理，但不是所有环都可解。
Spring Boot 3.x 默认不允许循环引用；打开开关也不是通用修复。

## 理解早期引用的目的

Spring 单例创建会区分完整单例、早期单例引用和生成早期引用的工厂。
第三层工厂允许后处理器参与早期引用创建，例如在需要时返回代理，
减少循环引用拿到原对象、最终容器却持有代理的不一致。

不能把“三级缓存”理解成通用对象缓存算法：这是 Bean 创建过程中的生命周期协作，
与 MyBatis 缓存、Redis 缓存无关。

## Java 使用上的边界

注入点 @Lazy 可以提供延迟解析代理，但如果构造/初始化时立刻调用它，依赖环仍可能暴露。
`ObjectProvider<T>` 允许在真正使用时获取 Bean，却不会自动消除业务上的递归调用。

你已熟悉依赖方向和解耦，此处不再扩展模块重构方案。
排查时读取 BeanCurrentlyInCreationException 中的依赖路径，确认构造器、初始化回调和代理创建分别发生在哪里。
