# 486 哪些逻辑必须有单元测试？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

必须有单元测试的是高复杂度、高风险、容易回归且可以脱离外部依赖验证的逻辑。电商系统里包括金额计算、优惠叠加、
状态机、幂等键、库存规则、风控规则、路由策略、参数校验、时间窗口和边界条件。

## 判断标准

一个逻辑是否必须写单元测试，可以看四个问题：

- 错了是否会造成资金、库存、订单或安全风险？
- 分支是否复杂，人工评审是否容易漏掉？
- 是否经常变化，未来回归风险高不高？
- 是否可以不依赖数据库、Redis、Kafka 就验证？

如果答案大多是肯定的，就应该优先写单元测试。

## 电商系统典型对象

金额计算必须测试，例如商品价、促销价、优惠券、运费、税费、积分和退款金额。金额错通常不是简单 bug，
而是直接的资金损失。

状态机必须测试，例如订单从待支付到已支付、已取消、已发货、已完成、退款中的合法流转。状态机错会导致脏状态。

幂等逻辑必须测试，例如支付回调幂等 key、Outbox event key、补偿任务幂等 key。幂等错会造成重复扣款或重复发货。

## 测试写法

单元测试要覆盖正常路径、边界条件、异常输入和非法状态。测试名要表达业务语义，例如
`shouldRejectCancelWhenOrderAlreadyShipped`，而不是只写 `testCancel`。

测试中尽量避免复杂 mock。纯逻辑可以直接构造对象输入，断言输出和状态变化。

## 电商系统实践

大型电商系统的 `order`、`payment`、`pricing`、`promotion`、`inventory` 和 `risk` 模块应优先保证核心规则有单元测试。
公共模块中的签名、脱敏、时间窗口、限流键和错误码映射也应该覆盖。
