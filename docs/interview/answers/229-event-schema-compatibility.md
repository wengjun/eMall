# 229 如何保证事件 schema 兼容？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

事件 schema 兼容要靠规则、注册表、兼容性检查、契约测试和灰度发布。
生产者不能随意删除字段、改字段类型或改变字段语义；消费者也要忽略未知字段，并兼容新旧版本一段时间。

事件一旦被多个服务订阅，就成为正式契约。

## 兼容规则

通常兼容：

- 新增可选字段。
- 新增消费者不依赖的字段。
- 新增枚举但消费者有默认处理。

通常不兼容：

- 删除字段。
- 修改字段类型。
- 改变字段含义。
- 把可选字段改为必填。
- 删除枚举值。

规则要在 CI 中自动检查。

## Schema Registry

可以使用 schema registry 管理：

- 事件名称。
- schema 版本。
- 兼容性策略。
- 生产者和消费者。
- 历史版本。

生产者发布新 schema 前先做兼容性校验。

## 消费者策略

消费者应：

- 忽略未知字段。
- 对缺失可选字段使用默认值。
- 明确不支持版本时进入死信。
- 不依赖未声明字段。
- 做契约测试。

兼容是生产者和消费者共同责任。

## 安全发布顺序

事件变更不能只检查最终代码是否兼容，还要保证任意发布中间态都兼容：

- 先发布能够同时读取新旧 schema 的消费者。
- 在 Schema Registry 和 CI 中执行兼容性检查，并用历史消息样例做反序列化回放。
- 再让生产者开始发送新增字段或新版本事件。
- 观察反序列化失败率、消费积压和死信后再继续放量。
- 确认所有消费者停止读取废弃字段后，才能在后续版本清理字段。

生产者和消费者发布顺序无法完全同步，因此向后兼容必须在混合版本运行期间成立。

## 电商系统实践

`OrderPaid` 事件新增 `paymentChannel` 字段通常兼容。

但把 `amountCents` 从数字改成字符串就是破坏性变更，会导致库存、财务和数据仓库消费失败。
