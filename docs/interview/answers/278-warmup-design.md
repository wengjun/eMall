# 278 如何做预热？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

预热是在服务承接真实高流量前，提前加载配置、缓存、连接、规则、模型和热点数据，并用小流量让运行时状态稳定。
它用于降低冷启动延迟、缓存击穿和恢复后瞬时过载风险。

预热不是启动成功，而是具备承载流量的准备过程。

## 预热内容

包括：

- 配置和规则。
- 数据库连接池。
- HTTP 连接池。
- Redis 连接。
- 本地缓存。
- 热点商品数据。
- 价格和库存快照。
- JVM JIT 和类加载。
- 推荐模型或风控规则。

不同服务预热内容不同。

## 预热方式

方式包括：

- 启动后主动加载热点数据。
- 小流量灰度。
- 影子请求。
- 定时刷新缓存。
- 连接池最小连接初始化。
- 大促前预计算。

预热要可观测，不能只打印日志表示完成。

## 风险控制

预热时要注意：

- 不要同时让所有实例回源。
- 控制预热并发。
- 失败可降级启动。
- 热点数据要有版本。
- 预热不能阻塞太久。

预热本身也可能打垮数据库。

## 在 eMall 项目中怎么讲？

大促前，商品、价格、库存和秒杀令牌要提前加载到缓存。

新实例上线后先只接少量流量，等连接池、缓存命中率和 P99 延迟稳定后再扩大流量。
