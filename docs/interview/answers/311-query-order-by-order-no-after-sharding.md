# 311 分库分表后如何按订单号查订单？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

分库分表后按订单号查订单，最好让订单号或订单 ID 中携带分片路由信息，直接定位到目标分片。
如果订单号没有路由信息，就需要订单路由表、全局索引表或搜索读模型，避免广播查询所有分片。

核心目标是把订单号查询变成单分片查询。

## 订单号携带路由

常见做法：

- 订单 ID 中包含时间和分片位。
- 订单号生成时写入分片号。
- 路由规则能从订单号反推出库表。

这样查询时不需要额外查路由表。

## 路由表方案

如果订单号本身不能计算分片，可以维护：

```text
order_route(order_no, shard_id, table_id, user_id, created_at)
```

先查路由表，再查目标分片。

路由表要高可用，并且和订单创建保持一致。

## 全局索引或读模型

也可以维护全局索引：

- 订单号到订单 ID。
- 订单号到用户 ID。
- 订单号到分片位置。

它可以通过本地事务或事件更新，但要处理一致性和补偿。

## 电商系统实践

大型电商系统订单号可以用趋势递增 ID，并在 ID 中保留分片位。

客服按订单号查询时，系统从订单号解析分片，直接路由到对应订单表，避免扫所有分片。
