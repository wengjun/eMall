# 669 当前系统是一体化架构还是微服务架构？

[返回按分类学习面试题](../README.md)

## 为什么问

这个问题用于了解真实的服务边界、数据所有权和调用方式，而不是获得“微服务”标签。相同标签下可能是自治服务，也可能是共享数据库的分布式单体。

## 重点听什么

- 服务按业务能力还是技术层拆分，谁拥有数据和接口契约。
- 核心链路同步调用多长，跨服务一致性如何恢复。
- 公共平台与业务团队的责任边界是否清楚。
- 架构如何从过去演进，当前哪些边界正在合并或拆分。

## 建议追问

“能否用一个核心请求说明完整调用链、故障时的降级边界，以及哪个团队负责最终业务结果？”
