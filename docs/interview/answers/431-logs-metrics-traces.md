# 431 日志、指标、Trace 分别解决什么问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

日志解决“发生了什么细节”，指标解决“系统整体状态如何”，Trace 解决“一次请求经过了哪些服务以及
哪里慢”。三者是互补关系，不是替代关系。

生产排障通常先看指标发现异常，再用 Trace 定位链路，最后用日志确认具体原因。

## 日志

日志适合：

- 记录业务事件。
- 记录异常堆栈。
- 记录关键参数摘要。
- 支持审计和追溯。
- 支持单请求细节排查。

日志信息丰富，但不适合作为高频聚合统计的唯一来源。

## 指标

指标适合：

- 监控 QPS。
- 监控错误率。
- 监控延迟。
- 监控资源使用率。
- 告警和趋势分析。

指标是低成本、可聚合的时间序列数据。

## Trace

Trace 适合：

- 还原请求链路。
- 定位跨服务耗时。
- 分析下游依赖。
- 发现串行调用和慢节点。
- 关联日志和指标。

微服务越多，Trace 越重要。

## 在 eMall 项目中怎么讲？

eMall 下单失败时，指标能发现订单成功率下降，Trace 能看到请求卡在库存、价格还是支付预创建，
日志能确认具体失败原因和业务参数摘要。

这三类数据需要用同一个 trace ID 串起来。
