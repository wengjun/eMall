# 078 线程和进程有什么区别？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

进程是操作系统资源分配的基本单位，拥有独立地址空间；线程是 CPU 调度的基本单位，同一进程内线程共享堆、
方法区、文件句柄等资源，但每个线程有自己的栈和程序计数器。进程隔离性强，线程通信成本低但共享状态更容易出并发问题。

Java 服务通常一个 JVM 进程内运行多个线程。

## 进程是什么？

进程可以理解为正在运行的程序实例。

它通常拥有：

- 独立虚拟地址空间。
- 文件句柄。
- 网络连接。
- 环境变量。
- 进程 ID。
- 操作系统资源配额。

一个 Java 微服务实例通常就是一个 JVM 进程。

## 线程是什么？

线程是进程内的执行流。

一个进程可以有多个线程。

每个线程有：

- 程序计数器。
- Java 虚拟机栈。
- 本地方法栈。
- 线程本地变量。

同一进程中的线程共享 heap、metaspace、打开的文件和连接等资源。

## 核心区别

| 对比项 | 进程 | 线程 |
| --- | --- | --- |
| 资源隔离 | 强 | 弱 |
| 地址空间 | 独立 | 同进程共享 |
| 创建成本 | 高 | 较低 |
| 通信方式 | IPC、网络 | 共享内存、队列 |
| 崩溃影响 | 通常影响自身 | 可能拖垮整个进程 |
| 并发风险 | 较低 | 共享状态竞争 |

## 为什么线程更容易出并发问题？

线程共享进程内存。

多个线程同时读写同一个对象，如果没有同步，就可能出现：

- 脏读。
- 丢失更新。
- 可见性问题。
- 指令重排序问题。
- 死锁。
- 竞态条件。

所以 Java 并发重点是治理共享状态。

## Java 中的线程

Java 中 `Thread` 对应 JVM 管理的线程，最终会映射到操作系统线程。

常见线程包括：

- main 线程。
- Web 请求线程。
- GC 线程。
- JIT 编译线程。
- MQ 消费线程。
- 定时任务线程。
- 业务线程池线程。

线程多了会增加调度和内存成本。

## 微服务和进程隔离

微服务通常把不同业务能力拆成不同进程或 Pod。

好处：

- 故障隔离。
- 独立扩容。
- 独立发布。
- 资源配额独立。
- 技术栈可演进。

代价是网络通信、分布式事务和运维复杂度增加。

## 在 eMall 项目中怎么讲？

eMall 的订单、库存、支付是不同微服务进程，进程之间通过 HTTP、RPC 或消息通信。

订单服务进程内部又有多个线程处理请求、调用下游、消费消息和执行定时任务。

服务拆分解决进程级隔离，线程池隔离解决进程内资源隔离，两者都需要设计。
