# 543 设计多区域电商系统。

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

多区域电商不能简单把所有数据库做双向复制。应按用户、商家或订单归属确定主写区域，把商品等可合并读模型
异步复制到各区域，并为区域故障定义明确的路由、写入降级、RPO、RTO 和数据回切流程。

## 核心拆解

- 全局入口根据归属目录、地域和健康状态路由，归属目录必须多副本持久化并支持缓存失效后的安全回源。
- 订单、支付和库存按聚合指定单一主写区域，商品、搜索等读模型允许跨区域异步复制。
- 跨区域事件携带全局事件 ID、聚合版本和来源区域，消费端处理重复、乱序及冲突。
- 演练区域隔离、归属目录故障和回切；用业务级 RPO/RTO、复制延迟及冲突数量验收。

## 深度完善：系统设计高分展开

围绕「设计多区域电商系统。」，系统设计题要按目标、规模、架构、数据、失败路径、演进六层展开。
不要只画组件图，必须讲清每个组件为什么存在，以及它如何在大促和故障场景下保持可控。
