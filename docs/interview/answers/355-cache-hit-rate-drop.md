# 355 缓存命中率下降如何排查？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

缓存命中率下降要从流量变化、key 命名变化、TTL 设置、缓存失效策略、热点变化、Redis 淘汰、
发布变更、数据预热和穿透攻击几方面排查。

关键是按 key 前缀、业务接口和时间线拆开看，而不是只看全局命中率。

## 排查维度

维度包括：

- 哪些接口命中率下降。
- 哪些 key 前缀下降。
- 是否刚发布版本。
- TTL 是否变短。
- 是否批量删除缓存。
- Redis 是否发生内存淘汰。
- 是否有大量不存在 key。
- 是否有新流量入口。

先定位范围，再分析原因。

## 常见原因

原因：

- key 版本变更导致旧缓存失效。
- 预热失败。
- TTL 过短。
- 随机参数进入 key。
- 缓存删除事件重复触发。
- Redis 内存不足触发淘汰。
- 缓存穿透。
- 热点商品切换。

命中率下降通常和发布或活动有关。

## 处理方式

处理：

- 回滚错误 key 生成逻辑。
- 临时延长 TTL。
- 执行热点预热。
- 增加空值缓存和布隆过滤器。
- 扩容 Redis 或调整淘汰策略。
- 限制异常来源。
- 降低回源并发。

处理时要同时保护数据库。

## 电商系统实践

大型电商系统商品详情命中率下降时，先按 `product:detail` 前缀看命中率，再对比发布、活动和商品编辑事件。

如果新版本把 key 从 `skuId` 改成 `productId`，会导致整体缓存失效。应立即回滚或兼容旧 key，
并执行分批预热，避免数据库被打满。
