# 608 当前系统最大的技术债是什么？

[返回按分类学习面试题](../README.md)

## 核心判断

最大的技术债不是某个类写得不够简洁，而是“设计目标很高，真实生产证据不足”。仓库表达了大量治理机制，但十亿用户、亿级日活和百万并发仍需要真实集群、流量模型和长期运行数据验证。

## 具体表现

- 模块和基础设施面较大，完整环境的部署、升级和故障联动成本高。
- 单元与容器集成测试能证明局部正确，不能替代跨可用区容量、混沌和灾备演练。
- 配置、告警阈值和容量参数需要由生产基线校准，示例默认值不是结论。
- 每项能力需要明确 owner、SLO、Runbook 和退出策略，否则会形成“有组件、无人运营”。

## 偿还路径

先定义可复现的最小生产拓扑和关键交易 SLO，再分阶段完成基准压测、故障注入、数据恢复和持续容量回归。对没有证据证明必要的组件做收敛，而不是继续增加功能。
