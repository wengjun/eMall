# 329 Redis 主从复制如何工作？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

Redis 主从复制是从节点连接主节点，先做全量同步或部分同步，然后持续接收主节点的写命令复制流。
主节点负责写，从节点复制数据并提供读扩展或故障切换基础。

复制可以提高读能力和可用性，但会带来复制延迟和一致性问题。

## 同步过程

主要过程：

- 从节点发送复制请求。
- 主节点判断能否部分同步。
- 不能部分同步时生成 RDB 做全量同步。
- 从节点加载 RDB。
- 主节点把同步期间的增量写命令发送给从节点。
- 后续持续发送写命令复制流。

网络抖动后如果复制 backlog 仍保留所需数据，可以做部分同步。

## 价值

价值包括：

- 读扩展。
- 故障切换基础。
- 数据冗余。
- 降低主节点读压力。
- 支持离线备份从从库执行。

读写分离要考虑从库延迟。

## 风险

风险包括：

- 主从复制延迟。
- 从库读到旧数据。
- 全量同步带来网络和磁盘压力。
- 主节点故障时可能丢失未复制数据。
- 从库也可能被热 key 打满。

Redis 主从不是强一致复制。

## 在 eMall 项目中怎么讲？

eMall 商品详情读可以走 Redis 从节点或集群副本，但库存扣减和订单状态不能依赖从节点的旧数据。

如果支付成功后马上查会话或短期状态，必须接受 Redis 主从延迟带来的短暂不一致，并准备兜底逻辑。
