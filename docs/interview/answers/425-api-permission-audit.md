# 425 如何做接口权限审计？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

接口权限审计要记录谁在什么时间、从哪里、以什么身份、访问了哪个接口、操作了什么资源、结果如何。
高危操作还要记录审批单、变更前后值和 trace ID。

审计日志要完整、可检索、防篡改，并和告警联动。

## 审计字段

字段包括：

- 主体 ID。
- 主体类型。
- 角色和权限。
- 接口和方法。
- 资源 ID。
- 来源 IP。
- user agent。
- 操作结果。
- trace ID。
- 时间戳。

高危接口需要更详细字段。

## 审计范围

范围：

- 登录和登出。
- 权限变更。
- 数据导出。
- 批量操作。
- 支付和退款。
- 改价和库存调整。
- 运维接口。
- 开放平台调用。

不是所有请求都需要同等审计粒度。

## 使用方式

审计用于：

- 事后追溯。
- 异常检测。
- 合规证明。
- 权限复核。
- 事故分析。

审计日志本身也要保护访问权限。

## 电商系统实践

大型电商系统批量退款接口要记录操作人、审批单号、订单列表摘要、退款金额、变更前后状态和 trace ID。

如果某个账号短时间导出大量订单，审计系统应触发告警。
