# 487 哪些逻辑必须有集成测试？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

必须有集成测试的是依赖真实中间件行为才能验证的逻辑，例如数据库事务、唯一索引幂等、MyBatis 映射、
Redis Lua、Kafka 生产消费、Outbox、分布式锁、HTTP 超时重试、配置加载和安全过滤链。

## 为什么单元测试不够

单元测试可以验证业务分支，但不能证明真实数据库是否提交成功、SQL 是否正确、索引是否生效、消息是否能反序列化、
事务回滚是否符合预期。很多生产事故不是纯逻辑错，而是代码和基础设施协作错。

集成测试的价值就是把这些协作风险提前暴露。

## 电商系统重点场景

订单创建必须测数据库事务。订单主表、明细表、支付单和 Outbox 事件必须要么一起成功，要么按设计补偿。

库存预占必须测并发和唯一约束。真实数据库的行锁、乐观锁和唯一索引行为很难只靠 mock 证明。

支付回调必须测幂等。重复回调、乱序回调和非法签名要在真实持久化环境中验证。

消息链路必须测序列化、生产、消费、重试和死信。否则上线后才发现 topic、group 或 schema 配置错误。

## 测试基础设施

推荐使用 Testcontainers 或本地 Docker 启动 MySQL、Redis、Kafka 等真实依赖。测试数据要可重复初始化，
测试结束后要清理或使用隔离 schema。

集成测试数量不需要像单元测试一样多，但核心交易链路必须覆盖。

## 在 eMall 项目中怎么讲？

eMall 的 `order`、`inventory`、`payment`、`event-platform`、`common` 和 `gateway` 模块中，涉及事务、消息、
安全过滤、签名校验和 Outbox 的部分都应该有集成测试。
