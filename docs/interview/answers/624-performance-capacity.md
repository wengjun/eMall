# 624 讲一次你提升性能或容量的经历。

[返回按分类学习面试题](../README.md)

## 本题考察

高分答案体现科学诊断：先建立负载模型和基线，再定位饱和资源，而不是凭经验调 JVM 参数或盲目扩容。

## 选材与证据

- 说明请求比例、数据分布、热点、并发和目标 P99，保证压测模型接近生产。
- 用 Trace、火焰图、慢 SQL、锁和队列指标证明瓶颈。
- 一次改变一个主要变量，并观察吞吐、延迟、错误率和资源利用率。
- 给出稳定容量、安全余量、扩容触发点和成本变化。

## 追问准备

准备解释压测与生产偏差、瓶颈后来移动到哪里、过载时如何退化，以及优化是否牺牲正确性。
