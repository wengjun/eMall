# 107 分段锁和库存桶有什么相似点？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

分段锁和库存桶的共同思想都是把一个热点资源拆成多个较小单元，让并发请求分散到不同段或桶上，
降低单点竞争。分段锁拆的是锁竞争，库存桶拆的是库存热点行或库存计数竞争。

本质都是用空间和复杂度换并发能力。

## 分段锁是什么？

分段锁是把一把全局锁拆成多把锁。

例如按 key 哈希：

```text
segment = hash(key) % segmentCount
```

不同 key 落到不同 segment，可以并发执行。

只有落到同一 segment 的请求才互相竞争。

## 库存桶是什么？

库存桶是把一个商品总库存拆成多个桶。

例如商品库存 1000，拆成 10 桶，每桶 100。

扣减时选择一个桶扣减，减少所有请求竞争同一行或同一 key。

适合热点商品秒杀。

## 相似点

相似点：

- 都是拆热点。
- 都降低单点竞争。
- 都提高并发度。
- 都需要路由规则。
- 都增加合并和一致性复杂度。

核心思想是“不要让所有请求挤在同一个点上”。

## 不同点

分段锁主要是并发控制手段。

库存桶是业务数据建模手段。

分段锁关注锁冲突。

库存桶还要关注：

- 总库存准确。
- 桶间均衡。
- 售罄判断。
- 回滚和补偿。
- 数据一致性。

库存桶比普通分段锁业务复杂度更高。

## 库存桶风险

库存桶要处理：

- 某些桶提前扣完。
- 总库存还有但选中桶没库存。
- 桶间不均衡。
- 退款回补到哪个桶。
- 对账和汇总。
- 防止超卖。

不能只拆桶，不设计一致性。

## 在 eMall 项目中怎么讲？

秒杀商品可以把库存按桶拆分到多个 Redis key 或数据库行。

请求按用户 ID 或随机策略选择桶扣减。

这样能降低单 key 热点，但最终仍要有总库存校验、售罄标记、补偿和对账。
