# 338 TTL 如何设置？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

TTL 要根据数据变化频率、一致性要求、回源成本、热点程度和故障兜底能力来设置。不是所有缓存都
设置同一个过期时间。

越稳定、回源越贵、可接受旧值的数据，TTL 可以更长。越敏感、变化越快的数据，TTL 应该更短或
通过事件驱动失效。

## 判断因素

因素包括：

- 数据变更频率。
- 业务能接受的陈旧时间。
- 回源数据库成本。
- 是否热点数据。
- 是否有主动失效事件。
- 是否需要防雪崩。
- Redis 内存容量。

TTL 是一致性和性能之间的权衡。

## 常见策略

策略：

- 商品基础信息用中长 TTL。
- 价格和库存展示用短 TTL。
- 活动配置用短 TTL 加主动刷新。
- 不存在数据用短 TTL 空值缓存。
- 热点 key 用逻辑过期。
- 所有批量缓存加随机抖动。

同一页面不同字段可以使用不同 TTL。

## 不设置 TTL 的风险

风险：

- 脏数据长期存在。
- 内存无法回收。
- 版本升级后旧结构残留。
- 删除事件丢失后无法自愈。

除非有明确生命周期管理，否则不建议永久缓存。

## 电商系统实践

大型电商系统商品基础信息可以设置 30 分钟到数小时 TTL，并通过商品变更事件主动删除。

价格可以设置几十秒到几分钟，库存展示更短。空值缓存设置几分钟。所有 TTL 加随机抖动，避免
大促前后大量 key 同时失效。
