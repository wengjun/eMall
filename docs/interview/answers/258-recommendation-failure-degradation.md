# 258 推荐服务故障如何降级？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

推荐服务故障通常可以降级，因为它影响转化和体验，但不应影响下单正确性。
常见降级方式是返回热门商品、类目热销、缓存结果、人工配置榜单，或者隐藏推荐模块。

降级目标是保住主链路，同时尽量减少用户体验和转化损失。

## 降级层级

可以分层：

- 个性化推荐。
- 用户相似推荐。
- 类目热销。
- 全站热销。
- 运营配置。
- 隐藏模块。

从个性化逐步退化到稳定兜底。

## 技术实现

实现方式：

- 熔断推荐接口。
- 设置短超时。
- 使用本地缓存或 Redis 缓存。
- 预计算热门榜单。
- BFF 层隐藏模块。
- 记录降级指标。

推荐不能拖慢商品详情页和首页主渲染。

## 注意事项

注意：

- 缓存结果要有过期时间。
- 热门榜单要提前预热。
- 降级内容要符合合规和风控。
- 恢复时要小流量放开。

推荐降级也可能影响收入，要监控点击率和转化率。

## 在 eMall 项目中怎么讲？

商品详情页调用推荐服务超过 `50ms` 时，可以返回同类目热销商品。

如果推荐服务持续失败，BFF 熔断推荐调用，首页保留核心商品和搜索入口。
