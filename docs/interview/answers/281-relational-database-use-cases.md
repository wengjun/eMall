# 281 关系型数据库适合解决什么问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

关系型数据库适合处理结构化数据、事务一致性、复杂条件查询、约束校验和需要可靠持久化的核心业务数据。
订单、支付、库存、账户、结算这类数据通常需要关系型数据库提供 ACID、索引、唯一约束和事务能力。

它不是所有场景的最佳选择，但在核心交易数据上仍然是基础设施。

## 适合场景

适合：

- 订单记录。
- 支付单。
- 库存流水。
- 用户账户。
- 商家结算。
- 售后单。
- 审计流水。

这些数据结构清晰，且对正确性要求高。

## 核心能力

关系型数据库提供：

- ACID 事务。
- 唯一约束。
- 外键或逻辑约束。
- 二级索引。
- SQL 查询。
- 并发控制。
- 崩溃恢复。

这些能力能降低核心数据错误概率。

## 不适合场景

不适合直接承载：

- 超大规模全文搜索。
- 高维推荐特征计算。
- 海量日志分析。
- 低价值高频埋点。
- 任意复杂报表。

这些应使用搜索引擎、数仓、OLAP 或日志平台。

## 在 eMall 项目中怎么讲？

订单主表和支付表应使用关系型数据库，因为需要事务、唯一约束、状态机和对账。

商品搜索和推荐召回不应直接压到 MySQL，而应使用搜索引擎和推荐系统。
