# 290 慢 SQL 如何分析？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

慢 SQL 分析要先确认慢在哪里，再看执行计划、索引、扫描行数、回表、排序、锁等待和返回数据量。
常用工具是慢查询日志、`EXPLAIN`、执行耗时分布、数据库监控和业务调用链。

不要一上来就加索引，要先确认瓶颈原因。

## 分析步骤

步骤：

- 从慢查询日志找到 SQL。
- 确认执行频率和影响面。
- 使用 `EXPLAIN` 看执行计划。
- 看是否走合适索引。
- 看扫描行数和返回行数。
- 看是否 filesort 或临时表。
- 看锁等待和事务。
- 看是否返回过多字段。

最后再决定优化方式。

## 常见原因

包括：

- 没有合适索引。
- 索引选择不合理。
- 回表太多。
- 深分页。
- 大范围扫描。
- 排序无法用索引。
- 锁等待。
- 查询字段过多。

不同原因对应不同优化手段。

## 优化方式

方式：

- 添加或调整联合索引。
- 改写查询条件。
- 使用覆盖索引。
- 限制时间范围。
- 游标分页。
- 拆分大查询。
- 异步导出。
- 降低事务持锁时间。

优化后要验证执行计划和线上指标。

## 电商系统实践

后台订单查询慢，不能直接给每个筛选字段都建索引。

应先看最常用查询路径、扫描行数、排序方式和是否深分页，再设计少量高价值联合索引或改为异步导出。
