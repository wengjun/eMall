# 199 如何做服务依赖治理？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

服务依赖治理要先看清依赖，再控制依赖。核心是建立服务目录、依赖拓扑、调用指标、分级管理、变更评审和故障演练。
关键链路要限制同步依赖数量，并为每个依赖定义超时、熔断、降级和负责人。

没有依赖治理，微服务数量越多，系统越不可控。

## 治理对象

需要治理：

- 服务调用关系。
- 数据库和缓存依赖。
- MQ topic 依赖。
- 第三方依赖。
- 配置和开关依赖。
- 部署和发布依赖。

依赖不仅是 HTTP 或 RPC 调用。

## 依赖信息

服务目录应记录：

- 服务负责人。
- 业务能力。
- 上游和下游。
- SLA。
- 限流规则。
- 降级策略。
- 变更窗口。
- 应急联系人。

这些信息要能从监控、注册中心和配置中自动补全。

## 治理动作

常见动作：

- 识别循环依赖。
- 控制核心链路依赖数量。
- 下线无用依赖。
- 为强依赖设置熔断。
- 为弱依赖设计降级。
- 变更前评估影响面。
- 定期做故障演练。

治理目标是减少未知依赖和隐式耦合。

## 电商系统实践

下单链路依赖库存、价格、优惠和风控，这些依赖都应标注为核心或准核心。

短信、推荐和数据分析属于弱依赖，不能同步阻塞下单。
