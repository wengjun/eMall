# 596 你为什么要做幂等表，而不是只在代码里判断状态？

[返回按分类学习面试题](../README.md)

## 核心判断

“先查询状态再执行”在并发下存在检查与写入之间的竞态，而且进程重启后内存判断会丢失。幂等表用数据库唯一约束原子地声明某个业务键只允许一个执行者，并可持久化执行结果供重试复用。

## 取舍依据

- 幂等键必须绑定调用方、操作类型和业务对象，避免不同请求误冲突。
- 请求摘要可防止同一键携带不同参数；成功结果可安全重放。
- 幂等记录与业务写入尽量处于同一本地事务，避免“占键成功、业务失败”的悬挂状态。
- 设计 TTL、分区和归档，防止高流量下表无限增长。

## 项目证据与边界

大型电商系统同时使用状态机、唯一业务约束和幂等记录：三者解决的问题不同。数据库本身已有天然唯一键且结果容易重建时，不必再堆一张通用幂等表。
