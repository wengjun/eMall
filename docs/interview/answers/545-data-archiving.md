# 545 设计数据归档系统。

[返回按分类学习面试题](../README.md)

## 题目

设计数据归档系统。

## 先给面试官的短答案

数据归档要按访问频率、法规保留期和恢复目标设计热、温、冷分层。归档过程必须可重复、可校验、可追踪，
只有在对象存储副本和校验清单确认后才能删除在线数据。

## 核心拆解

- 按时间和业务主键切分归档批次，使用稳定游标，避免 OFFSET 扫描和长事务。
- 导出文件包含 schema 版本、记录数、主键范围和校验和，清单状态机记录导出、验证、删除与失败原因。
- 查询服务先查在线数据，再按授权访问归档索引；恢复演练验证 RTO，而不是只证明文件存在。
- 删除要遵守法律保留、诉讼冻结和隐私擦除要求，并限制任务 QPS，避免影响主库。

## 深度完善：系统设计高分展开

围绕「设计数据归档系统。」，系统设计题要按目标、规模、架构、数据、失败路径、演进六层展开。
不要只画组件图，必须讲清每个组件为什么存在，以及它如何在大促和故障场景下保持可控。

通用的六层分析、可恢复数据模型和取舍表达集中在
[共享模型：系统设计回答框架](../shared-answer-models.md#系统设计回答框架)。本题应继续围绕上文列出的领域不变量展开，
不能机械套用通用的电商表结构和中间件清单。
