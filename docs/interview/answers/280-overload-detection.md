# 280 如何判断系统已经进入过载？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

系统进入过载通常表现为吞吐不再增长、延迟快速升高、错误率增加、队列堆积、线程池和连接池耗尽。
判断时不能只看 CPU，要同时看资源指标、排队指标、延迟分位数和业务成功率。

过载的典型信号是系统花更多时间排队和重试，而不是处理有效请求。

## 技术指标

指标包括：

- CPU 长时间高位。
- GC 时间增加。
- 线程池活跃数满。
- 队列长度持续增长。
- 数据库连接池耗尽。
- HTTP 连接池等待增加。
- P95/P99 延迟升高。
- 超时和 5xx 增加。

队列持续增长是强信号。

## 业务指标

还要看：

- 下单成功率下降。
- 支付成功率下降。
- 库存扣减失败率升高。
- 用户取消率增加。
- 客服投诉增加。

技术指标正常但业务成功率下降，也说明系统可能有局部过载。

## 吞吐曲线

压测时如果继续增加并发：

- QPS 不再上升。
- 延迟明显升高。
- 错误率上升。

这说明系统已经越过稳定容量点。

## 在 eMall 项目中怎么讲？

秒杀期间如果订单服务 QPS 不再增加，但 P99 从 `200ms` 升到 `3s`，线程池队列持续增长，
说明系统已过载，应立即限流或降级。
