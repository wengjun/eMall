# 319 读写分离有什么一致性问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

读写分离的主要一致性问题是主库写入后，从库复制存在延迟，用户立刻读从库可能读不到刚写的数据。
这会导致下单后看不到订单、支付后状态仍是待支付等读己之写问题。

解决方式包括关键读走主库、会话一致性、延迟检测、读路由和最终一致提示。

## 典型问题

场景：

- 用户提交订单写主库成功。
- 立刻查询订单列表读从库。
- 从库还没同步。
- 用户看不到新订单。

业务上会造成困惑。

## 解决方式

方式包括：

- 写后短时间读主库。
- 按用户会话路由主库。
- 检测从库延迟。
- 延迟过高时停止读从。
- 关键链路读主库。
- 页面提示处理中。

不能所有读都无脑走从库。

## 取舍

读主库会增加主库压力。

读从库会有延迟风险。

需要按业务重要性选择，例如订单提交后的确认页应读主库，普通历史列表可以读从库。

## 电商系统实践

用户支付成功后刷新订单详情，订单详情应读主库或使用会话一致性路由。

运营后台大范围历史查询可以走从库或数仓。
