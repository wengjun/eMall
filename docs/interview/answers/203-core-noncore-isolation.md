# 203 核心链路和非核心链路如何隔离？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

核心链路隔离的目标是让推荐、广告、通知、报表等非核心能力故障时，不影响下单、支付、库存等核心交易。
常用手段包括服务分级、线程池隔离、连接池隔离、限流、熔断、降级、异步化、数据隔离和资源配额。

隔离不是只在代码里判断异常，而是从运行资源到业务流程都要隔离。

## 隔离维度

维度包括：

- 服务依赖隔离。
- 线程池隔离。
- 连接池隔离。
- 缓存和数据库资源隔离。
- MQ topic 和消费组隔离。
- 部署集群隔离。
- 配置和开关隔离。
- 告警和值班隔离。

共享资源越多，故障越容易传播。

## 主链路治理

核心链路要：

- 减少同步依赖。
- 明确强依赖和弱依赖。
- 弱依赖必须可降级。
- 下游调用设置超时预算。
- 失败快速返回或使用兜底。
- 禁止大查询和慢任务抢占资源。

核心资源应优先保障交易成功。

## 非核心处理方式

非核心能力可以：

- 异步消费事件。
- 使用独立线程池。
- 使用独立队列。
- 使用缓存默认值。
- 失败后补偿。
- 高峰期主动降级。

非核心链路要接受延迟和降级。

## 电商系统实践

下单接口可以同步依赖库存和价格，但不应同步依赖短信、推荐刷新和数据仓库写入。

短信失败不能导致下单失败，推荐失败可以隐藏模块，数据仓库写入失败可以通过 MQ 重试。
