# 202 如何做服务分级？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

服务分级是按业务重要性、故障影响、收入影响、用户影响和依赖程度给服务划分等级。
分级后，不同等级服务使用不同的 SLA、容量冗余、发布门禁、告警策略、应急预案和演练频率。

没有分级，资源会平均分配，真正关键的链路得不到足够保护。

## 常见分级

可以划分为：

- P0：全站核心交易和登录支付链路。
- P1：重要业务能力，故障明显影响用户体验。
- P2：普通业务能力，可短时间降级。
- P3：后台、离线、辅助系统。

具体等级应结合公司业务定义。

## 分级依据

依据包括：

- 是否影响下单和支付。
- 是否影响登录和鉴权。
- 是否影响资金和库存正确性。
- 是否影响大面积用户。
- 是否被多个核心服务依赖。
- 是否有替代或降级方案。

分级要定期复核，业务变化后服务等级也会变化。

## 分级后的治理

治理差异：

- P0 服务需要更高可用性和容量冗余。
- P0 发布要更严格灰度和回滚。
- P0 告警要更低延迟。
- P2/P3 可以接受更长恢复时间。
- 非核心服务要能被主链路降级。

分级要落到流程和资源上。

## 在 eMall 项目中怎么讲？

订单、库存、支付、用户鉴权属于 P0 或 P1。

推荐、广告、报表、数据仓库通常不应阻塞交易主链路，可以按 P2/P3 管理，并提供降级策略。
