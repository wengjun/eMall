# 265 如何做请求合并？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

请求合并是把短时间内对同一资源的多个相同请求合并成一次下游调用，其他请求复用结果。
它常用于热点商品、配置、价格、库存展示和缓存击穿保护，能减少重复查询和下游压力。

请求合并要注意超时、错误传播、隔离和结果缓存时间。

## 合并方式

常见方式：

- 单进程内 singleflight。
- 短时间窗口批量聚合。
- 对同一 key 的请求共享 Future。
- 多 key 批量查询。
- 缓存缺失时只允许一个请求回源。

关键是按业务 key 合并。

## 适合场景

适合：

- 热点商品详情。
- 商品价格展示。
- 配置读取。
- 字典数据。
- 用户短时间重复刷新。
- 缓存击穿保护。

不适合有副作用的写请求。

## 风险

风险包括：

- 一个慢请求拖住多个等待者。
- 下游失败影响所有合并请求。
- 合并粒度过大导致延迟升高。
- 不同权限用户结果混用。

合并 key 必须包含权限、租户和上下文。

## 在 eMall 项目中怎么讲？

大促商品详情页同一 SKU 的价格查询可以在 BFF 或商品服务内做 singleflight。

同一时刻多个请求只让一个请求回源价格服务，其余请求等待并复用结果。
