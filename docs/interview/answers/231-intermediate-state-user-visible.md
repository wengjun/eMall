# 231 用户看到中间状态是否可接受？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

是否可接受取决于业务语义。分布式系统中，中间状态很常见，但必须让用户看到可理解、可恢复、不会误导的状态。
例如“支付处理中”“退款处理中”可以接受，但“支付成功却显示订单不存在”不可接受。

中间状态要被产品化，而不是把系统内部不一致直接暴露给用户。

## 可接受的中间状态

常见可接受状态：

- 待支付。
- 支付处理中。
- 库存确认中。
- 退款处理中。
- 履约处理中。
- 售后审核中。

这些状态本身就是业务流程的一部分。

## 不可接受的中间状态

不可接受：

- 用户已付款但订单消失。
- 库存扣减成功但订单失败且不退款。
- 页面显示相互矛盾的状态。
- 用户无法知道下一步。
- 状态长期停留且无人处理。

不可接受的核心是用户权益不清晰或无法恢复。

## 设计要求

要求包括：

- 状态命名用户可理解。
- 给出下一步提示。
- 设置超时处理。
- 后台补偿可推进状态。
- 客服和运营可查询。
- 状态变化有通知。

每个中间状态都要有退出路径。

## 电商系统实践

支付回调可能晚于用户页面刷新。

页面可以显示“支付结果确认中”，并提示稍后刷新。后台通过支付回调、主动查询和对账把订单推进到已支付或支付失败。
