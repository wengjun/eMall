# 223 消费失败后如何重试？

[返回按分类学习面试题](../README.md)

## 题目

消费失败后如何重试？

## 先给面试官的短答案

消费失败后要区分临时失败和永久失败。临时失败可以重试，永久失败应直接进入失败记录或死信。
重试要有最大次数、退避策略、错误分类、告警和幂等保护，不能无限快速重试。

重试是恢复手段，也可能变成流量放大器。

## 错误分类

可重试：

- 下游超时。
- 临时网络错误。
- 数据库连接短暂失败。
- 限流后稍后可恢复。

不可重试：

- 参数格式错误。
- 业务资源不存在且不会恢复。
- 权限错误。
- Schema 不兼容。

错误分类决定处理路径。

## 重试策略

策略包括：

- 固定间隔重试。
- 指数退避。
- 延迟队列。
- 分级重试 topic。
- 最大重试次数。
- 超限进入死信。

高并发系统通常要使用退避和抖动，避免同时重试冲击下游。

## 工程要点

要点包括：

- 消费处理幂等。
- 记录失败原因。
- 记录重试次数。
- 对同一业务键避免并发重试。
- 可观测重试堆积。
- 重试失败后告警。

无限重试会隐藏问题并拖垮系统。

## 在 eMall 项目中怎么讲？

库存服务消费订单支付事件时，如果数据库短暂不可用，可以延迟重试。

如果事件缺少必要字段或订单状态非法，应进入死信并告警，而不是一直重试。

## 专家级完整回答

```text
消费失败后先分类。临时性错误可以重试，永久性业务错误不应无限重试。
重试要设置最大次数、退避、抖动和死信路径，并记录失败原因和重试次数。

消费者必须幂等，因为每次重试都可能在上一次部分成功后再次执行。重试堆积和失败率也要监控告警。
```

## 回答评分点

高分答案应该覆盖：

- 先区分可重试和不可重试错误。
- 重试要有最大次数。
- 退避和抖动防止冲击下游。
- 超限进入死信。
- 消费者必须幂等。
