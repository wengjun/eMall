# 253 半开状态为什么要小流量探测？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

半开状态小流量探测是为了验证下游是否真正恢复，而不是把全部流量瞬间放回去。
下游刚恢复时缓存、连接池、线程池和数据加载都可能还没预热，全量流量会导致二次雪崩。

平滑恢复比快速恢复更重要。

## 全量放开的风险

风险包括：

- 下游刚启动就被打满。
- 缓存未预热导致数据库压力升高。
- 连接池未建立完成。
- JIT 和运行时状态未稳定。
- 积压请求同时冲击下游。

下游可能刚恢复又再次失败。

## 小流量探测看什么？

观察：

- 成功率。
- P95 和 P99 延迟。
- 下游错误码。
- 线程池和连接池。
- CPU 和 GC。
- 业务成功率。

只看是否返回 `200` 不够，还要看延迟和资源是否稳定。

## 放量策略

常见策略：

- 固定少量探测请求。
- 按比例逐步恢复。
- 成功一段时间后扩大流量。
- 失败立即回到熔断。
- 对核心接口恢复更保守。

恢复过程要可观测。

## 电商系统实践

库存服务从故障中恢复后，订单服务不能立刻把全部下单流量打过去。

应先放少量库存预占请求，观察成功率和延迟，再逐步恢复正常流量。
