# 266 如何做热点隔离？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

热点隔离是把异常高流量的用户、SKU、商家、活动或接口从普通流量中隔离出来，防止热点拖垮整体系统。
常用手段包括热点识别、单独限流、独立线程池、独立缓存、分片打散、队列削峰和专用集群。

目标是热点失败不影响普通用户。

## 热点来源

热点可能来自：

- 秒杀 SKU。
- 爆款商品。
- 大商家活动。
- 明星直播带货。
- 恶意爬虫。
- 热门搜索词。

热点通常集中访问同一资源。

## 隔离手段

手段包括：

- 按 SKU 或活动限流。
- 热点 key 拆分。
- 独立缓存 key。
- 单独线程池。
- 专用队列。
- 专用数据库分片。
- 活动专用服务集群。

越靠近入口识别热点，保护效果越好。

## 动态识别

需要监控：

- 单 key QPS。
- 单 key 错误率。
- 单 key 延迟。
- 数据库热点行锁等待。
- Redis 热 key。

热点治理要动态化，不能只靠人工配置。

## 在 eMall 项目中怎么讲？

秒杀 SKU 可以使用独立活动入口、令牌桶、库存缓存和专用队列。

普通商品下单走普通链路，秒杀流量不能和普通订单争抢同一线程池和数据库连接池。
