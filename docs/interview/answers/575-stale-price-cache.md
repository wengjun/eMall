# 575 商品价格显示旧值，如何排查缓存一致性问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

先以价格事实库和生效规则确认正确价格，再比较缓存值的版本、TTL、失效事件及各级缓存。
核心风险是旧事件覆盖新值或本地缓存未失效；下单必须再次获取价格快照，不能信任展示缓存。

## 核心拆解

- 按商品、渠道、区域和时间检查价格版本，区分缓存旧值与促销规则计算错误。
- 追踪价格事务、Outbox、Kafka 消费和 Redis/本地缓存失效，确认是否存在乱序或消息丢失。
- 对受影响 Key 按版本失效并暂停问题发布，不能全量 FLUSH Redis 制造回源雪崩。
- 使用单调版本阻止旧事件覆盖，监控缓存版本落后时间，并核对错误价格产生的订单。
