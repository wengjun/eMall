# 310 分库分表后如何按用户查订单？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

如果订单主表按用户 ID 分片，按用户查订单可以直接路由到单分片。
如果主表按订单 ID 分片，就需要用户订单索引表、读模型、搜索索引或路由表来支持用户维度查询。

不要让用户订单列表每次都扫所有分片。

## 按用户分片

查询流程：

```text
userId -> 计算分片 -> 查询用户订单列表
```

优点是简单高效。

缺点是写入均匀性和商家查询可能需要额外设计。

## 用户订单索引表

如果订单主表按订单 ID 分片，可以维护：

```text
user_order_index(user_id, order_id, created_at, status)
```

按用户 ID 分片该索引表，列表页先查索引表，再按订单 ID 查询详情或直接覆盖列表字段。

## 读模型

也可以通过事件构建用户订单读模型。

订单创建、支付、取消、履约事件更新用户维度订单视图。

读模型允许最终一致，但要有补偿和对账。

## 在 eMall 项目中怎么讲？

用户订单列表是高频读接口，可以维护按 `user_id` 分片的订单列表读模型。

订单主表按订单 ID 均匀写入，读模型通过订单事件异步更新，并支持状态和时间游标分页。
