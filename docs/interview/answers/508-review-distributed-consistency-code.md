# 508 如何评审分布式一致性相关代码？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

评审分布式一致性代码要重点看事务边界、幂等、状态机、消息可靠性、重试、补偿、乱序处理、并发冲突和观测。
核心问题是：任何一步失败、重复、乱序或超时时，系统是否仍能达到最终一致，且不会产生重复副作用。

## 关键检查项

事务边界：业务数据和事件记录是否在同一事务内提交，是否存在写一半成功的问题。

幂等：接口、消息消费者、补偿任务和回调是否都有业务唯一键和重复处理策略。

状态机：状态流转是否单向、合法，旧状态是否会覆盖新状态。

消息可靠性：是否使用 Outbox、重试、死信和消费端幂等，是否处理发送成功但确认失败。

补偿：失败后是否有可恢复路径，补偿任务是否幂等、限速和可观测。

并发：是否依赖唯一索引、乐观锁、条件更新或分布式锁，锁失败后是否安全。

## 常见问题

常见错误包括先发消息再提交事务、重复消费没有幂等、重试没有退避、补偿任务扫描条件过宽、
状态机允许回退、异常被吞掉、失败没有告警和人工处理入口。

## 在 eMall 项目中怎么讲？

eMall 的订单创建、库存预占、支付回调、退款和履约都涉及分布式一致性。评审时要沿状态流和消息流检查：
如果任意服务超时、重复发送消息、重复消费或补偿重入，是否仍然不超卖、不重复扣款、不重复发货。
