# 430 如何处理数据合规删除和历史订单保留？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

数据合规删除和历史订单保留要区分个人可删除信息与法定或业务必须保留的交易记录。用户可以要求
删除或匿名化个人信息，但历史订单可能因财务、税务、审计、售后和风控需要保留。

常见做法是去标识化、匿名化、字段清除和访问限制，而不是简单物理删除所有订单。

## 数据分类

分类：

- 账号资料。
- 联系方式。
- 地址。
- 订单交易记录。
- 支付流水。
- 发票和税务记录。
- 客服和售后记录。

不同数据有不同保留要求。

## 删除策略

策略：

- 可删除数据直接删除。
- 敏感字段匿名化。
- 历史订单保留必要字段。
- 地址和手机号脱敏或清除。
- 支付和税务记录按法规保留。
- 删除请求全链路审计。

要和法务、合规要求对齐。

## 系统难点

难点：

- 数据分布在多个服务。
- 缓存和搜索索引也要清理。
- 数据仓库和备份存在延迟。
- 删除后仍要支持审计。
- 不能破坏财务对账。

删除是流程，不是单表 SQL。

## 电商系统实践

大型电商系统用户注销后，可以清除或匿名化手机号、地址、昵称等个人信息。

历史订单保留订单号、金额、商品摘要和财务必要字段，但把收货人、手机号和详细地址脱敏或删除。
搜索、缓存、数据仓库也要接收删除事件。
