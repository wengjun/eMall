# 339 TTL 为什么要加随机抖动？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

TTL 加随机抖动是为了避免大量缓存 key 在同一时刻过期，导致请求集中回源数据库，引发缓存雪崩。
随机抖动可以把过期时间打散，让回源压力分摊到更长时间窗口。

它是缓存雪崩治理中成本很低但非常有效的手段。

## 没有抖动的问题

如果大量 key 同时写入，并设置相同 TTL，就会在同一时间集中失效。

例如大促前预热 100 万个商品详情，统一设置 30 分钟 TTL。30 分钟后大量请求同时未命中 Redis，
数据库会瞬间承受巨大回源压力。

## 抖动方式

常见方式：

```text
ttl = baseTtl + random(0, jitter)
```

例如基础 TTL 为 30 分钟，随机增加 0 到 5 分钟。

也可以根据业务使用正负抖动，但要避免 TTL 过短影响命中率。

## 注意点

注意：

- 抖动不能替代主动失效。
- 热点 key 仍要做逻辑过期。
- 抖动范围要和业务陈旧容忍度匹配。
- 批量预热必须加抖动。
- 多级缓存也要考虑过期错峰。

随机抖动解决的是集中失效，不解决单热点击穿。

## 电商系统实践

大型电商系统商品详情缓存预热时不能统一设置相同 TTL。可以把基础 TTL 设置为 30 分钟，再加 0 到
5 分钟随机抖动。

这样即使大量商品同时预热，也不会在同一秒集中回源数据库。
