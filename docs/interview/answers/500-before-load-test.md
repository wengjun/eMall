# 500 压测前要准备什么？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

压测前要明确目标、场景、容量模型、测试数据、环境隔离、监控指标、限流保护、回滚预案和压测停止条件。
不能直接拿工具打流量，否则结果不可解释，还可能影响真实生产。

## 目标和场景

先明确压测目标：验证峰值 QPS、P99 延迟、稳定性、容量水位、扩容效果，还是寻找瓶颈。不同目标决定不同压测方式。

场景要来自真实业务比例。例如浏览商品、搜索、加购、下单、支付、查询订单的流量比例不同，不能只压一个接口就代表全站。

## 数据和环境

测试数据要足够真实，包括用户、SKU、库存、价格、优惠券、订单和支付通道。热点 SKU、长尾 SKU、不同地区和不同用户等级
都可能影响结果。

环境要尽量接近生产，并明确是否压生产。压生产必须有隔离标记、压测账号、压测订单、压测支付通道和清理机制。

## 观测和保护

压测前要准备指标面板、日志查询、链路追踪、数据库监控、Redis 监控、Kafka lag、线程池和连接池指标。

还要准备停止条件，例如错误率超过阈值、数据库 CPU 超过阈值、支付通道异常、真实用户指标受影响时立即停止。

## 电商系统实践

大型电商系统的 `loadtest` 模块可以定义交易链路压测场景。压测前应准备测试 SKU、测试库存、压测用户、压测支付回调和清理任务，
并用 `traffic`、`reliability` 和 `operations` 模块提供限流、观测和止损。
