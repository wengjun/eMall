# 488 Mock 的优点和风险是什么？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

Mock 的优点是让测试更快、更稳定、更容易隔离外部依赖和异常分支。风险是 mock 可能和真实行为不一致，
导致测试通过但生产失败；过度 mock 还会让测试绑定实现细节，重构成本高，覆盖不到组件协作问题。

## Mock 的优点

Mock 适合替代慢、不稳定或难构造的外部依赖。例如第三方支付通道、风控接口、短信服务和远程库存服务。
通过 mock 可以稳定模拟成功、失败、超时、异常和边界响应。

Mock 也能隔离被测对象，让单元测试只关注当前类的业务逻辑。这样测试运行快，失败定位清晰。

## Mock 的风险

最大的风险是“模拟错了”。例如真实支付通道回调字段是字符串金额，mock 却用数字；真实 HTTP 客户端超时抛出的异常类型
和 mock 不一致；真实数据库唯一约束会报错，mock repository 却直接返回成功。

第二个风险是测试实现细节。测试只验证某个方法被调用几次，而不是验证业务结果，会让代码稍微重构就大量失败。

第三个风险是掩盖集成问题。序列化、事务、SQL、连接池、消息 topic 和安全过滤链都不能靠 mock 完整验证。

## 使用原则

Mock 应该用于边界依赖，而不是 mock 掉所有领域对象。测试应该优先断言业务结果，而不是过度断言调用细节。

对关键基础设施行为，要用集成测试补充。单元测试和 mock 负责快，集成测试负责真。

## 在 eMall 项目中怎么讲？

eMall 可以 mock 第三方支付通道、短信服务、外部风控供应商，但不应该只 mock 掉库存扣减和订单事务。
库存防超卖、支付回调幂等、Outbox 投递必须用真实数据库或消息组件验证。
