# 400 搜索延迟升高如何排查？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

搜索延迟升高要从查询流量、慢查询、分片负载、聚合排序、缓存命中率、OpenSearch 集群状态、
JVM、磁盘 IO、网络和最近发布变更排查。

排查时要按查询类型和索引拆分，不能只看整体 P99。

## 查询侧

检查：

- 是否出现复杂查询。
- 是否大分页。
- 是否高基数字段聚合。
- 是否脚本排序。
- 是否通配符或模糊查询过多。
- 热门词是否突增。

复杂查询经常是延迟上升原因。

## 集群侧

检查：

- shard 是否倾斜。
- CPU 是否升高。
- JVM GC 是否异常。
- 磁盘 IO 是否打满。
- search thread pool 是否排队。
- rejected 请求是否增加。
- 节点是否掉线。

集群资源和分片分布要一起看。

## 应用侧

检查：

- 搜索服务超时配置。
- 连接池是否耗尽。
- 缓存命中率是否下降。
- 最近发布是否改变查询 DSL。
- 下游广告或排序服务是否变慢。

搜索延迟不一定都在 OpenSearch。

## 电商系统实践

大型电商系统搜索 P99 升高时，先按关键词搜索、类目筛选、价格排序和聚合查询拆开看。

如果发现大分页和复杂聚合导致慢查询，可以限制页码、关闭高成本聚合，并临时降级到基础排序。
