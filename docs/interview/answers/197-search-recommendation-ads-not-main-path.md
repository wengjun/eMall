# 197 搜索、推荐、广告为什么通常不放在交易主链路？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

搜索、推荐、广告属于流量和转化链路，核心目标是曝光、召回、排序和点击转化；交易主链路关注下单、库存、支付和履约。
它们 SLA、数据模型、容量特征和故障容忍度不同，放在主链路会增加下单延迟和故障半径。

推荐和广告失败可以降级，支付和库存失败则会影响交易正确性。

## 差异在哪里？

差异包括：

- 交易链路要求正确性和一致性。
- 推荐广告更关注效果和实时特征。
- 搜索需要复杂索引和排序。
- 推荐广告可容忍降级或空结果。
- 交易链路不能被非核心能力拖慢。

把它们混在一起会让系统目标冲突。

## 正确关系

它们应通过事件和数据平台连接：

- 交易服务发布订单、支付、履约事件。
- 推荐系统消费行为数据更新模型。
- 搜索系统消费商品变更更新索引。
- 广告系统消费曝光和点击事件。

在线交易链路不依赖它们完成下单。

## 降级策略

推荐失败可以：

- 返回默认推荐。
- 返回热门商品。
- 返回空模块。
- 使用缓存结果。

广告失败可以隐藏广告位，但不能影响用户结算和支付。

## 在 eMall 项目中怎么讲？

订单提交接口不应同步调用广告计费、推荐模型刷新或搜索索引更新。

订单完成后发布事件，搜索、推荐、广告和数据仓库异步消费，这样交易主链路保持短而稳定。
