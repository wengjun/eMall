# 449 如何设计告警级别？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

告警级别应按用户影响、业务损失、影响范围、持续时间和是否需要立即人工介入来设计。常见级别是
P0、P1、P2、P3，越高级越强调立即响应和升级。

级别不是按技术指标大小随意定，而是按业务影响定。

## P0

P0 通常是：

- 全站不可用。
- 下单或支付大面积失败。
- 数据丢失。
- 资金错误。
- 安全重大事故。

需要立即拉群、升级和指挥。

## P1

P1 通常是：

- 核心链路部分不可用。
- 单区域或部分渠道严重受影响。
- 错误率持续升高。
- 重要依赖故障。

需要值班立即处理。

## P2 和 P3

P2：

- 非核心功能异常。
- 有降级方案。
- 影响范围有限。

P3：

- 趋势风险。
- 容量预警。
- 低优先级缺陷。
- 可工作时间处理。

不同级别对应不同响应。

## 在 eMall 项目中怎么讲？

eMall 支付成功率大面积下降应定为 P0。推荐服务失败但可降级为空，通常是 P2。

磁盘容量未来三天可能不足，可以是 P3 容量预警，但如果已经影响 Kafka 写入，就要升级。
