# 399 搜索服务故障如何降级？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

搜索服务故障时要保护核心交易链路。可降级为热门商品、类目推荐、缓存搜索结果、静态活动页、
部分过滤条件关闭、超时快速失败或提示稍后重试。

搜索是导购链路，不能让它拖垮商品、价格、库存和订单服务。

## 降级方式

方式：

- 返回热门商品榜。
- 返回类目默认商品。
- 使用缓存的上一版搜索结果。
- 关闭复杂排序和聚合。
- 降级个性化和广告混排。
- 超时快速失败。
- 限制搜索 QPS。

降级要分级，不是只有全开或全关。

## 保护措施

保护：

- 搜索调用设置短超时。
- 熔断 OpenSearch 异常。
- 查询复杂度限制。
- 大分页限制。
- 热门查询缓存。
- 独立资源池隔离。

搜索故障不能扩散到主站。

## 用户体验

体验上可以：

- 展示热门推荐。
- 提示搜索繁忙。
- 保留类目导航。
- 允许用户进入商品详情。
- 对大促会场使用静态兜底页。

降级仍要给用户可继续浏览的路径。

## 在 eMall 项目中怎么讲？

eMall 搜索集群延迟升高时，可以关闭复杂聚合和个性化重排，只保留基础关键词搜索。

如果搜索完全不可用，首页和类目页返回预热好的热门商品缓存。下单链路不依赖搜索服务，因此仍能
保持核心交易可用。
