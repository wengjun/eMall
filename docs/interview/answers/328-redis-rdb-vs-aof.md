# 328 Redis 持久化 RDB 和 AOF 有什么区别？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

RDB 是定期生成某一时刻的数据快照，恢复快但可能丢失最近一段数据。AOF 是追加写命令日志，
数据丢失窗口更小，但文件更大，恢复时需要重放命令。

生产中经常组合使用 RDB 和 AOF，并根据业务的 RPO、性能和恢复速度要求做取舍。

## RDB

特点：

- 保存某个时间点的数据快照。
- 文件紧凑。
- 恢复速度快。
- 对灾备和迁移友好。
- 两次快照之间的数据可能丢失。

RDB 更适合快速恢复和冷备。

## AOF

特点：

- 记录写命令。
- 可配置每秒刷盘或每次刷盘。
- 数据丢失窗口更小。
- 文件通常更大。
- 需要重写压缩日志。
- 恢复时要重放命令。

AOF 更适合降低数据丢失风险。

## 生产取舍

考虑因素：

- 缓存是否允许丢失。
- Redis 是否承载准状态数据。
- 恢复速度要求。
- 磁盘 IO 能力。
- 文件大小。
- 主从和集群能力。

如果 Redis 只是缓存，重点是快速重建。如果 Redis 存放限流计数或短期状态，要评估丢失影响。

## 在 eMall 项目中怎么讲？

eMall 不应该把订单最终状态只放在 Redis，因此订单核心数据不依赖 Redis 持久化。

Redis 主要保存商品缓存、会话、限流计数和热点数据。商品缓存丢失后可以从数据库重建。
限流计数短暂丢失会影响保护能力，因此需要结合网关限流和本地保护兜底。
