# 388 为什么电商搜索通常不用 MySQL 直接实现？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

电商搜索需要全文检索、分词、相关性排序、多条件过滤、聚合、召回、排序和高并发查询。MySQL 更
适合事务和结构化查询，不适合大规模复杂搜索和相关性计算。

所以通常使用 OpenSearch、Elasticsearch 或专门搜索引擎构建搜索读模型。

## 搜索需求

电商搜索需要：

- 关键词分词。
- 倒排索引。
- 多字段相关性。
- 类目和品牌过滤。
- 价格区间过滤。
- 销量和评分排序。
- 广告和运营干预。
- 高亮和纠错。

这些不是传统 OLTP 数据库的强项。

## MySQL 的限制

限制：

- `LIKE` 查询难以走高效索引。
- 多条件组合复杂。
- 相关性排序能力弱。
- 聚合和分页成本高。
- 高并发搜索会影响交易库。
- 分词和召回能力有限。

交易库不能被搜索流量拖垮。

## 搜索引擎优势

优势：

- 倒排索引。
- 分词器。
- 相关性打分。
- 分布式查询。
- 聚合统计。
- 读模型可重建。

搜索引擎牺牲部分实时一致性，换取搜索能力和吞吐。

## 在 eMall 项目中怎么讲？

eMall 商品库负责商品主数据和事务一致性，搜索服务维护商品搜索文档。

商品变更通过事件同步到搜索索引。搜索结果可能短暂滞后，但不会影响下单最终校验。
