# 418 手机号为什么不能明文存储？

[返回按分类学习面试题](../README.md)

## 题目

手机号为什么不能明文存储？

## 先给面试官的短答案

手机号属于个人敏感信息，明文存储会让数据库、备份、日志、测试环境或内部查询泄露时直接暴露用户
隐私，带来合规、风控和品牌风险。

生产系统应采用加密存储、脱敏展示、最小权限、审计和密钥管理。

## 风险

风险包括：

- 数据库泄露。
- 备份泄露。
- 日志泄露。
- 测试数据泄露。
- 内部人员越权查询。
- 第三方报表扩散。

手机号还能关联身份、地址和交易行为。

## 治理方式

方式：

- AES-GCM 加密保存。
- HMAC hash 支持精确查询。
- 页面脱敏展示。
- 导出审批。
- 权限最小化。
- 访问审计。
- 测试环境数据脱敏。

敏感数据治理要覆盖全生命周期。

## 展示原则

展示时：

- 普通客服只看脱敏号码。
- 高权限操作才可解密。
- 解密行为记录审计。
- 批量导出需要审批。

不是所有内部员工都应该看到明文手机号。

## 在 eMall 项目中怎么讲？

eMall 用户表中手机号不明文保存。查询使用 `phone_hash`，展示使用 `phone_ciphertext` 解密后脱敏为
`138****1234`。

客服查看完整手机号必须有工单授权，并记录审计日志。

## 专家级完整回答

```text
手机号是个人敏感信息，明文存储会在数据库、备份、日志、测试环境和内部查询泄露时直接暴露用户
隐私。它还能和订单、地址、支付行为关联，风险更大。

生产中应加密存储、HMAC hash 查询、脱敏展示、最小权限、访问审计、导出审批和测试数据脱敏。安全
设计不能只保护数据库本身，还要覆盖数据流转全链路。
```

## 回答评分点

高分答案应该覆盖：

- 手机号是敏感个人信息。
- 明文泄露影响严重。
- 加密存储和 HMAC 查询。
- 脱敏展示。
- 权限、审计和导出审批。
