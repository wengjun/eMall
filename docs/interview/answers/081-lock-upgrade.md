# 081 Java 17 还需要背偏向锁和锁升级路径吗？

[返回按分类学习面试题](../README.md)

## 版本边界比旧图更重要

偏向锁是 HotSpot 曾经为“反复由同一线程获取锁”做的优化。
JDK 15 起默认禁用并弃用相关选项，Java 17 不是“所有 synchronized 必经偏向锁”的运行方式。
默认禁用也不等于这个版本已经完全移除了实现。

因此不需要为了 Java 17 开发熟练度，反复背“无锁 -> 偏向 -> 轻量级 -> 重量级”的历史口令。

## 仍值得保留的机制

synchronized 的互斥、可重入和内存可见性是语言语义；对象头、CAS、栈上锁记录、
monitor 膨胀是 HotSpot 实现细节，具体路径可能随 JDK 版本变化。

低竞争时尽量减少阻塞成本，竞争或其他条件触发时可能膨胀为 ObjectMonitor。
“重量级”也不表示每次获取都必须进行一次 OS 阻塞。
锁状态还涉及回收/消胀，不能把旧图当成对象整个生命周期只能单向变化的保证。

读 Java 17 代码时，优先掌握
[080](080-synchronized-principle.md) 的字节码与 monitor，
再用 [076](076-diagnose-lock-contention.md) 的 JFR/线程栈验证实际竞争。
不在本题重讲通用锁粒度设计。
