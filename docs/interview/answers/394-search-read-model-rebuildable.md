# 394 搜索读模型可以重建吗？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

搜索读模型必须设计成可重建。因为搜索索引不是事实来源，可能因为 schema 变更、分词调整、数据
损坏、同步失败或集群迁移而需要重建。

可重建能力是生产级搜索系统的基本要求。

## 为什么要重建

原因：

- 索引 mapping 变更。
- 分词器升级。
- 搜索文档字段调整。
- 历史同步缺失。
- 索引数据损坏。
- 集群迁移。
- 排序特征重新计算。

没有重建能力，搜索系统无法长期演进。

## 重建来源

来源：

- 商品主库。
- 价格读模型。
- 库存快照。
- 评价统计。
- 商家信息。
- 事件日志。

重建要能从可信数据源重新生成文档。

## 重建要求

要求：

- 不影响线上搜索。
- 支持新旧索引并行。
- 支持进度和失败记录。
- 支持增量追平。
- 支持校验和切换。
- 支持回滚。

这通常通过双索引和别名切换实现。

## 电商系统实践

大型电商系统搜索索引可以创建 `product_search_v2`，从商品库全量扫描构建，再消费增量事件追平。

校验通过后，把搜索别名从 `product_search_v1` 切到 v2。如果发现问题，可以快速切回旧索引。
