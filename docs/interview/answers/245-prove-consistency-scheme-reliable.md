# 245 如何证明一致性方案是可靠的？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

证明一致性方案可靠，不能只画流程图，要列出所有失败点，并说明每个失败点如何恢复、是否幂等、是否可观测、是否可对账。
还要用测试、故障演练、压测、混沌工程和线上指标验证。

可靠性来自完整的失败模型和可执行的恢复闭环。

## 分析失败点

要覆盖：

- 本地事务失败。
- MQ 发送失败。
- 消息重复。
- 消费失败。
- ack 失败。
- 下游超时。
- 补偿失败。
- 对账发现差异。
- 节点宕机。
- 网络分区。

每个点都要有处理策略。

## 证明问题

要回答：

- 数据会不会丢？
- 消息会不会丢？
- 重复会不会产生副作用？
- 乱序会不会导致状态回退？
- 补偿能否重复执行？
- 差异能否被发现？
- 人工能否介入？

这些问题比单纯描述架构更能体现深度。

## 验证手段

手段包括：

- 单元测试。
- 集成测试。
- 契约测试。
- 故障注入。
- 死信重放演练。
- 对账演练。
- 压测。
- 线上监控和告警。

没有验证的方案只是设计假设。

## 在 eMall 项目中怎么讲？

订单支付一致性方案要证明：支付成功事件不丢，订单更新幂等，重复事件不会重复扣库存，
订单和支付差异能被对账发现，并且补偿任务可以修复。
