# 245 如何证明一致性方案是可靠的？

[返回按分类学习面试题](../README.md)

## 题目

如何证明一致性方案是可靠的？

## 先给面试官的短答案

证明一致性方案可靠，不能只画流程图，要列出所有失败点，并说明每个失败点如何恢复、是否幂等、是否可观测、是否可对账。
还要用测试、故障演练、压测、混沌工程和线上指标验证。

可靠性来自完整的失败模型和可执行的恢复闭环。

## 分析失败点

要覆盖：

- 本地事务失败。
- MQ 发送失败。
- 消息重复。
- 消费失败。
- ack 失败。
- 下游超时。
- 补偿失败。
- 对账发现差异。
- 节点宕机。
- 网络分区。

每个点都要有处理策略。

## 证明问题

要回答：

- 数据会不会丢？
- 消息会不会丢？
- 重复会不会产生副作用？
- 乱序会不会导致状态回退？
- 补偿能否重复执行？
- 差异能否被发现？
- 人工能否介入？

这些问题比单纯描述架构更能体现深度。

## 验证手段

手段包括：

- 单元测试。
- 集成测试。
- 契约测试。
- 故障注入。
- 死信重放演练。
- 对账演练。
- 压测。
- 线上监控和告警。

没有验证的方案只是设计假设。

## 在 eMall 项目中怎么讲？

订单支付一致性方案要证明：支付成功事件不丢，订单更新幂等，重复事件不会重复扣库存，
订单和支付差异能被对账发现，并且补偿任务可以修复。

## 共性一致性模型

状态机、Outbox、幂等、重试、对账和补偿的统一闭环及 Java 17 示例见
[共享模型：最终一致、状态机和补偿](../shared-answer-models.md#最终一致状态机和补偿)。

## 专家级完整回答

```text
证明一致性方案可靠，要基于失败模型逐点分析，而不是只描述正常流程。
我会列出事务失败、消息失败、重复、乱序、宕机、补偿失败和对账差异，并说明每个场景的恢复路径。

然后用自动化测试、故障注入、死信重放、对账演练、压测和线上指标验证，形成可观测、可恢复、可审计的闭环。
```

## 回答评分点

高分答案应该覆盖：

- 要分析失败模型。
- 每个失败点要有恢复路径。
- 幂等、补偿、对账和审计是证明重点。
- 需要故障演练和测试验证。
- 可靠性要通过指标持续观察。
