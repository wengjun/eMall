# 373 消息体过大有什么问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

消息体过大会增加网络带宽、磁盘 IO、Broker 内存、复制延迟、消费反序列化成本和重试成本，还会
降低批处理效率，严重时导致 Producer 发送失败或 Consumer 处理超时。

消息系统适合传递事件，不适合传输大对象。

## 主要危害

危害包括：

- Producer 发送耗时增加。
- Broker 磁盘占用增加。
- 副本复制变慢。
- Consumer 拉取和反序列化变慢。
- 网络带宽被占用。
- 重试和死信成本变高。
- 批量消息数量下降。

大消息会拖慢整条链路。

## 常见原因

原因：

- 事件中携带完整对象。
- 携带图片、富文本或大列表。
- 把查询结果当消息传输。
- schema 缺少边界。
- 不做字段裁剪。

事件应该表达事实，而不是复制整个数据库行集合。

## 治理方式

方式：

- 只携带关键字段快照。
- 大对象放对象存储，消息放引用。
- 压缩但不依赖压缩掩盖设计问题。
- 设置消息大小告警。
- 对 schema 做评审。
- 消费端限制单批数据量。

大消息治理要前置到设计阶段。

## 在 eMall 项目中怎么讲？

eMall 商品变更事件不应携带完整详情页 HTML、所有图片和全部评价。

正确做法是携带 `skuId`、变更类型、版本和关键字段。搜索服务需要重建文档时，可按 ID 回查商品
服务或读商品库的读模型。
