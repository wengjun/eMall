# 293 索引越多为什么写入越慢？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

每次插入、更新、删除数据时，数据库不仅要修改数据行，还要维护所有相关索引。
索引越多，B+Tree 插入、页分裂、日志写入、锁竞争和缓存占用越多，写入自然越慢。

索引提升读性能，但会增加写入和存储成本。

## 写入时发生什么？

写入需要：

- 修改聚簇索引。
- 修改每个二级索引。
- 写 redo log。
- 写 undo log。
- 可能触发页分裂。
- 维护统计信息。

二级索引越多，维护动作越多。

## 更新索引列更贵

如果更新的字段属于索引列：

- 旧索引项要删除。
- 新索引项要插入。
- 可能涉及多个索引。

频繁变化的字段不适合随意建很多索引。

## 存储和缓存成本

索引多会导致：

- 磁盘占用增加。
- Buffer Pool 被索引占用。
- 备份恢复变慢。
- DDL 成本增加。

读性能可能也会因为缓存被稀释而下降。

## 电商系统实践

订单表不能为了后台所有筛选条件都建单列索引。

应围绕核心查询设计少量联合索引，把复杂低频查询转到数仓或异步导出。
