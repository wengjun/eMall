# 351 Redis 限流如何实现？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

Redis 限流常用固定窗口、滑动窗口、令牌桶和漏桶。实现上通常使用计数器、ZSet 或 Lua 脚本保证
检查和更新的原子性。

生产级限流要明确限流维度、时间窗口、拒绝策略、降级策略和 Redis 故障时的兜底。

## 固定窗口

固定窗口使用 key 记录某个窗口内的请求数。

示例：

```text
rate:user:10001:api:createOrder:202604301647
```

请求时自增计数，并设置过期时间。优点是简单，缺点是窗口边界可能出现突刺。

## 滑动窗口

滑动窗口可以用 ZSet 记录请求时间戳。

流程：

- 删除窗口外的旧时间戳。
- 统计当前窗口内数量。
- 未超过阈值则写入当前请求。
- 超过阈值则拒绝。

这类操作要用 Lua 保证原子性。

## 令牌桶

令牌桶适合允许一定突发流量。

系统按固定速率生成令牌，请求拿到令牌才允许执行。Redis 可以保存令牌数和上次补充时间，通过
Lua 计算补充和扣减。

## 在 eMall 项目中怎么讲？

eMall 可以在网关按用户、IP、接口和商家维度限流。例如下单接口限制单用户短时间提交次数。

秒杀接口更适合令牌桶和活动令牌，普通查询接口可以固定窗口或滑动窗口。Redis 故障时，网关要有
本地限流兜底，不能完全失去保护。
