# 336 如何设计商品详情缓存？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

商品详情缓存要按读多写少、强展示、可短暂不一致的特点设计。通常使用多级缓存，包括本地缓存、
Redis 缓存和数据库回源，并结合 TTL 抖动、空值缓存、热点保护、异步刷新和变更失效。

商品详情可以短暂展示旧数据，但价格、库存和上下架状态要分开处理。

## 数据拆分

商品详情不要所有字段一把缓存。

可以拆为：

- 商品基础信息。
- 图片和描述。
- 价格。
- 库存展示。
- 促销信息。
- 评价摘要。
- 上下架状态。

不同数据的一致性要求不同，TTL 也不同。

## 缓存层次

常见层次：

- CDN 缓存静态图片。
- 应用本地缓存热点商品。
- Redis 缓存商品聚合信息。
- 数据库作为最终数据源。

热点商品可以用本地缓存降低 Redis 压力。

## 更新策略

策略：

- 商品编辑后发事件删除或刷新缓存。
- 缓存值携带商品版本，只有更新版本的事件才能覆盖或失效当前值。
- TTL 加随机抖动。
- 热点商品逻辑过期。
- 不存在商品缓存空值。
- 价格和库存独立查询或独立缓存。
- 上下架变更优先保证及时失效。

不能让商品详情缓存影响下单正确性。

数据库商品记录是权威事实，缓存只是可丢失、可重建的读模型。事件重复或乱序时，不能让旧商品版本覆盖新缓存。

## 电商系统实践

大型电商系统的商品详情页可以缓存 `product:detail:{skuId}`，value 是基础信息、图片和描述摘要。

价格使用 `pricing` 服务实时或短 TTL 缓存，库存展示使用 `inventory` 的可售快照，下单时仍要走
库存条件扣减。这样展示缓存可以弱一致，交易判断仍由核心服务保证。
