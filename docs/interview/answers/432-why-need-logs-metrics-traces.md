# 432 为什么三者都需要？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

只看指标不知道具体请求发生了什么，只看日志很难快速发现整体趋势，只看 Trace 不一定知道业务影响
有多大。日志、指标和 Trace 分别覆盖宏观监控、链路定位和细节确认。

生产系统需要三者组合才能做到快速发现、快速定位和快速修复。

## 只有指标的问题

指标能看到：

- 错误率升高。
- P99 升高。
- QPS 突增。
- CPU 升高。

但指标通常无法告诉你某个订单为什么失败。

## 只有日志的问题

日志能看到细节，但问题是：

- 数据量大。
- 聚合成本高。
- 很难直接做实时告警。
- 跨服务串联困难。

日志适合确认原因，不适合单独承担监控体系。

## 只有 Trace 的问题

Trace 能看链路，但问题是：

- 采样可能漏掉请求。
- 不一定有完整业务上下文。
- 不适合作为长期趋势统计。
- 不能替代业务指标。

Trace 适合定位链路，不适合衡量全局健康度。

## 在 eMall 项目中怎么讲？

eMall 支付成功率下降时，指标能告诉我们影响范围，Trace 能定位支付回调链路是否变慢，日志能确认
是签名失败、状态机冲突还是第三方返回异常。

三者缺一项，排障都会变慢。
