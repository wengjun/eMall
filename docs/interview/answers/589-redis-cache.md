# 589 你为什么用 Redis 缓存，而不是只靠数据库？

[返回按分类学习面试题](../README.md)

## 核心判断

商品详情、活动资格等读多写少且存在热点，若所有请求直达 MySQL，峰值容量会由最昂贵的数据库层承担。Redis 的价值是吸收重复读取和热点流量，不是替代权威数据源。

## 取舍依据

- 先用数据库容量预算、热点分布和命中率证明需要缓存，而不是“有 Redis 就缓存”。
- 采用 Cache Aside 时要定义失效顺序、TTL、随机抖动和可接受的不一致窗口。
- 空值缓存、布隆过滤、互斥重建和逻辑过期分别处理穿透、击穿和雪崩，不能混为一谈。
- 缓存故障时必须限流、降级或返回旧值，不能把全部流量无界回源数据库。

## 项目证据与边界

eMall 将 Redis 用于可重建读模型、限流和短期状态，订单与支付事实仍以数据库为准。低流量、强一致且查询简单的功能直接查库更合理，避免增加双写和运维成本。
