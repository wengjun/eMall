# 342 缓存和数据库短暂不一致如何接受？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

缓存和数据库短暂不一致能否接受，取决于业务语义。展示类数据通常可以接受秒级或分钟级陈旧，
交易决策类数据不能只依赖缓存，必须以数据库、库存服务或风控服务的最终校验为准。

生产级设计不是追求所有缓存强一致，而是明确一致性边界和补偿机制。

## 如何判断能否接受

判断维度：

- 是否影响资金。
- 是否影响库存扣减。
- 是否影响风控决策。
- 是否影响用户承诺。
- 是否只是页面展示。
- 陈旧数据最长能容忍多久。

资金、库存、权益类场景要更严格。

## 可接受场景

通常可接受：

- 商品描述短暂旧值。
- 评价摘要延迟更新。
- 热销榜延迟刷新。
- 推荐结果短暂不准。
- 浏览量统计延迟。

这些问题影响体验，但不应影响交易正确性。

## 不可直接接受场景

高风险场景：

- 支付状态。
- 订单状态。
- 库存扣减。
- 优惠券核销。
- 账户余额。
- 风控黑名单。

这些场景需要最终数据源校验、幂等和补偿。

## 在 eMall 项目中怎么讲？

eMall 商品详情缓存可以短暂旧，但下单时必须重新校验价格、库存、上下架状态和购买资格。

如果页面显示有货，但下单时库存服务条件扣减失败，系统应该返回库存不足。这是可接受的弱一致
展示，而不是交易错误。
