# 354 Redis 故障时系统如何降级？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

Redis 故障时要防止所有请求直接回源数据库。系统应按业务重要性采取本地缓存、限流、熔断、返回
旧值、默认值、只读模式、排队或拒绝非核心请求。

降级目标不是保持所有功能完整，而是保护核心交易链路和数据库。

## 故障影响

可能影响：

- 商品详情缓存失效。
- 会话校验变慢。
- 限流计数失效。
- 分布式锁不可用。
- 购物车缓存不可用。
- 热点数据回源数据库。

不同业务要有不同预案。

## 降级策略

策略：

- 本地缓存返回旧值。
- 非核心推荐降级为空。
- 商品详情限制回源并发。
- 下单接口保留核心校验。
- Redis 锁不可用时拒绝高风险操作。
- 网关启用本地限流。
- 数据库熔断保护。

不能让缓存故障演变成数据库故障。

## 恢复策略

恢复时要注意：

- 不要立刻放开全部流量。
- 缓存逐步预热。
- 回源限速。
- 观察命中率和数据库压力。
- 确认 Redis 延迟恢复正常。

恢复也需要平滑，避免二次雪崩。

## 电商系统实践

大型电商系统的 Redis 故障时，商品详情可以返回本地旧缓存，推荐和热榜可以降级为空。

下单链路不能直接跳过库存和价格校验。如果 Redis 限流不可用，网关启用本地限流；如果库存热点
令牌不可用，秒杀接口应该限流或暂停，而不是把请求全部打到库存库。
