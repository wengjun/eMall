# 456 如何设计一次故障演练？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

故障演练要先定义目标和边界，再设计故障场景、影响范围、回滚方案、观察指标、参与人员和成功标准。
演练不是制造混乱，而是验证系统和团队是否能发现、隔离、降级和恢复。

生产演练必须有止损机制。

## 演练准备

准备：

- 明确演练目标。
- 明确影响范围。
- 选择低峰时段或灰度范围。
- 准备回滚方案。
- 通知相关人员。
- 确认监控和告警。
- 准备 Runbook。

没有止损方案不能演练。

## 场景设计

场景：

- Redis 不可用。
- Kafka 延迟。
- 数据库主从延迟。
- 下游支付超时。
- 单实例宕机。
- 网络延迟。
- 线程池耗尽。

场景要贴近真实风险。

## 成功标准

标准：

- 告警是否及时。
- 值班是否按 Runbook 处理。
- 降级是否生效。
- 核心链路是否保护住。
- 恢复是否符合 RTO。
- 数据是否一致。

演练后要复盘。

## 电商系统实践

大型电商系统可以演练 Redis 商品缓存不可用。目标是验证商品详情是否启用本地旧值、回源是否限流、数据库
是否被保护、Redis 恢复后是否平滑预热。

演练范围可以先限制到灰度环境或小流量租户。
