# 440 订单成功率下降如何排查？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

订单成功率下降要先确认影响范围和下降阶段，是创建订单失败、库存失败、价格校验失败、风控拒绝、
支付预创建失败，还是超时导致用户放弃。然后按时间线关联发布、流量、依赖、错误码和业务指标。

核心是先拆漏斗，再定位具体环节。

## 先看范围

先确认：

- 全站还是部分接口。
- 全用户还是部分渠道。
- 所有商品还是部分 SKU。
- 所有商家还是部分商家。
- 是否和发布或活动时间重合。

范围决定排查方向。

## 拆交易漏斗

拆分：

- 商品详情访问。
- 加购。
- 结算。
- 提交订单。
- 库存预占。
- 价格校验。
- 风控校验。
- 支付单创建。

每一段都要有转化和失败原因。

## 技术排查

检查：

- 订单服务错误率。
- 库存服务错误率。
- 价格服务延迟。
- 风控拒绝率。
- 数据库慢 SQL。
- Redis 或 MQ 异常。
- 线程池和连接池。

成功率下降可能来自业务拒绝，也可能来自技术故障。

## 止血和恢复

- 按版本、区域和渠道确认最近变更，异常与发布相关时暂停灰度并回滚。
- 库存、价格或风控过载时限流并隔离非核心能力，不能把真实失败降级成“下单成功”。
- 恢复后按 requestId 核对订单、库存预占和 Outbox，修复悬挂预占、重复订单或丢失事件。

## 电商系统实践

大型电商系统下单成功率下降时，先按错误码看失败集中在库存不足、价格变更、风控拒绝还是系统异常。

如果某些热点 SKU 库存预占失败率升高，排查库存桶、Redis 令牌、数据库行锁和秒杀流量隔离。
