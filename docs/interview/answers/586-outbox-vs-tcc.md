# 586 你为什么选择本地事务加 Outbox，而不是 TCC？

[返回按分类学习面试题](../README.md)

## 核心判断

订单创建后的事件传播允许短暂延迟，更重要的是业务写入与“待发送事件”不能一成一败。Outbox 用一个本地事务解决原子落库，再由 Relay 至少一次投递；TCC 要求每个参与方实现 Try、Confirm、Cancel，更适合必须提前锁定多方资源且业务能够提供补偿语义的少数场景。

## 取舍依据

- Outbox 降低参与方耦合，但必须处理重复消费、乱序、积压、毒消息和事件表清理。
- TCC 能缩短跨服务不一致窗口，但有空回滚、悬挂、幂等、资源长期冻结和协调器可用性成本。
- 两者都不是“自动一致”：Outbox 依赖对账与补偿，TCC 依赖正确的业务补偿和状态防护。
- 只有单库内部强一致需求时，普通本地事务比两者都简单。

## 项目证据与边界

大型电商系统的交易事件采用状态机、Outbox Relay、消费幂等和补偿任务组合。支付扣款等不能简单反向操作的能力，不应为了形式统一强行套 TCC；若未来出现跨资源的短时强协调需求，再按业务语义局部引入。
