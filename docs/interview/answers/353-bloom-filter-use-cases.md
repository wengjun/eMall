# 353 布隆过滤器适合什么场景？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

布隆过滤器适合判断某个元素是否可能存在，尤其适合大规模集合的快速预判，例如商品 ID 是否存在、
用户是否可能存在、爬虫 URL 去重和缓存穿透防护。

它的特点是可能误判存在，但不会漏判已加入的数据。

## 工作原理

布隆过滤器由位数组和多个哈希函数组成。

加入元素时，多个哈希函数计算多个位置，并把这些位置置为 1。查询元素时，如果任意位置为 0，
说明一定不存在。如果所有位置都是 1，说明可能存在。

## 适合场景

适合：

- 缓存穿透防护。
- 大规模 ID 存在性判断。
- URL 去重。
- 黑名单预过滤。
- 推荐去重初筛。

这些场景能接受少量误判。

## 不适合场景

不适合：

- 需要精确判断不存在误判的场景。
- 需要频繁删除的场景。
- 数据量远超设计容量的场景。
- 误判会造成资金或权益错误的场景。

误判率和容量要提前估算。

## 在 eMall 项目中怎么讲？

eMall 可以把已上架商品 ID 加入布隆过滤器。商品详情请求先查布隆过滤器，如果判断一定不存在，
直接返回不存在或访问空值缓存，避免打到数据库。

如果布隆过滤器判断可能存在，再查 Redis 和数据库。误判最多多查一次数据库，不会把存在商品过滤掉。
