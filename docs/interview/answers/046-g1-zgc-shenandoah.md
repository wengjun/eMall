# 046 G1、ZGC、Shenandoah 的设计目标有什么不同？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

G1 是面向服务端的通用低停顿收集器，目标是在吞吐和可预测暂停之间取得平衡。
ZGC 和 Shenandoah 更偏低延迟，目标是把 GC 暂停控制在很短时间，适合大堆和低延迟场景。

选择 GC 不能只看名字，要结合堆大小、延迟目标、吞吐、CPU 成本、JDK 版本和压测数据。

## G1 的目标

G1 将堆划分为多个 Region，不再简单按连续年轻代和老年代区域理解。

特点：

- 面向服务端应用。
- 尽量提供可预测暂停。
- 适合中大型堆。
- 在吞吐和延迟之间平衡。

G1 通常是现代 Java 服务的常见默认选择。

## ZGC 的目标

ZGC 目标是超低暂停，适合大堆、低延迟场景。

特点：

- 并发执行大量 GC 工作。
- 暂停时间很短。
- 对应用延迟更友好。
- 可能需要更多 CPU 或内存开销。

适合：

- 低延迟 API。
- 大堆内存服务。
- 对 P99/P999 敏感的服务。

## Shenandoah 的目标

Shenandoah 也是低暂停 GC，和 ZGC 类似，目标是减少停顿时间。

它通过并发移动对象等技术降低暂停，但具体可用性和表现取决于 JDK 发行版和版本。

## 如何选择？

不要直接说“ZGC 一定最好”。

选择维度：

- 服务是否延迟敏感。
- 堆有多大。
- CPU 是否充足。
- 吞吐是否比延迟更重要。
- JDK 版本和运行环境是否成熟。
- 团队是否有运维经验。
- 压测数据如何。

## 电商服务中的选择

网关、下单、支付回调：

- 对延迟敏感。
- 要关注 P99。
- 可考虑 G1 或低延迟 GC，并通过压测验证。

离线报表、批处理：

- 吞吐优先。
- 暂停敏感度较低。
- 不一定需要最强低延迟 GC。
