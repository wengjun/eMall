# 246 高并发系统的瓶颈通常在哪里？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

高并发系统瓶颈通常出现在数据库、缓存热点、下游服务、线程池、连接池、锁竞争、网络带宽、序列化和单点资源。
定位瓶颈要看 CPU、内存、IO、连接数、队列长度、响应时间分位数和业务成功率。

不要只盯 QPS，尾延迟和错误率更能说明系统是否健康。

## 常见瓶颈

包括：

- 数据库慢查询和锁。
- 热点 key。
- 缓存击穿。
- MQ 积压。
- 下游超时。
- 线程池打满。
- HTTP 连接池耗尽。
- 分布式锁竞争。
- 大对象序列化。
- 网关和负载均衡瓶颈。

瓶颈往往出现在共享资源。

## 定位指标

指标包括：

- CPU 使用率。
- GC 暂停。
- 数据库连接数。
- 慢 SQL。
- 缓存命中率。
- 线程池队列长度。
- P95 和 P99 延迟。
- 错误率。
- 限流和熔断次数。

业务指标也要同时看，例如下单成功率。

## 解决思路

思路：

- 缓存和预计算。
- 分库分表。
- 读写分离。
- 限流削峰。
- 异步化。
- 热点打散。
- 降级非核心能力。
- 扩容和隔离。

先定位，再优化，避免盲目扩容。

## 在 eMall 项目中怎么讲？

秒杀场景瓶颈可能不是 Java 代码，而是库存热点行、Redis 热点 key、MQ 积压或数据库连接池。

要通过压测和监控定位具体瓶颈，再做热点库存预扣、令牌限流和异步削峰。
