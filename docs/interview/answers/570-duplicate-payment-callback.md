# 570 支付渠道重复回调导致大量冲突日志，是否是事故？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

重复回调本身通常是支付渠道的至少一次投递语义，不一定是事故；如果幂等处理后只产生可降噪日志，业务是正常的。
若出现状态冲突、重复事件或告警风暴，则需要修复幂等边界和可观测性。

## 核心拆解

- 按渠道交易号、支付单号和回调签名确认重复请求内容一致，排除伪造或金额变化。
- 支付状态使用条件更新，回调处理记录设置唯一约束，已成功请求直接返回渠道期望的成功响应。
- 检查重复回调是否再次发布 Outbox、推进订单或触发履约；有副作用才属于业务事故。
- 将预期重复计为指标而非错误堆栈，异常重复率和内容冲突才告警。

## 深度完善：生产事故 Runbook

围绕「支付渠道重复回调导致大量冲突日志，是否是事故？」，事故题不要直接猜根因。高分回答要按时间线推进：先止血，再定位，再恢复，
最后补齐长期防线。面试官更看重你是否能控制影响面，而不是一次性猜中答案。
