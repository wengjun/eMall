# 635 讲一次你做长期架构演进规划的经历。

[返回按分类学习面试题](../README.md)

## 本题考察

路线图不是技术愿望清单，而是把业务目标、当前风险和可迁移步骤连接起来。选择跨多个季度且根据数据调整过的真实规划。

## 选材与证据

- 用能力、SLO、成本和组织瓶颈描述当前状态与目标状态。
- 将演进拆成独立产生价值、兼容旧系统且可回滚的阶段。
- 为每阶段定义触发阈值、依赖、owner、成功指标和退出条件。
- 说明如何平衡功能交付与平台投入，以及哪些计划因新证据被修改。

## 追问准备

准备解释最大迁移风险、如何避免双系统永久共存、路线图被业务打断时如何重排，以及哪项长期判断后来证明错误。
