# 248 如何做容量估算？

[返回按分类学习面试题](../README.md)

## 题目

如何做容量估算？

## 先给面试官的短答案

容量估算要从业务目标倒推技术资源：用户规模、DAU、峰值系数、请求路径、读写比例、响应时间、数据库容量、缓存容量、
MQ 吞吐、机器资源和冗余系数。

估算只是起点，必须通过压测和线上监控校准。

## 估算步骤

步骤：

- 明确 DAU 和峰值并发。
- 估算核心接口 QPS。
- 拆解每个接口的下游调用。
- 估算数据库读写 QPS。
- 估算缓存命中率和容量。
- 估算 MQ 消息量。
- 估算机器 CPU、内存和网络。
- 加上冗余和故障切换容量。

核心链路要单独估算。

## 峰值系数

电商流量有明显峰值：

- 大促。
- 秒杀。
- 发券。
- 晚高峰。
- 推送触达。

不能用日均流量直接设计容量。要按峰值小时、峰值分钟甚至峰值秒估算。

## 冗余设计

容量要考虑：

- N+1 冗余。
- 单可用区故障。
- 下游抖动。
- 发布期间双版本。
- 缓存失效。
- MQ 堆积追赶。

生产容量不能刚好够用。

## 在 eMall 项目中怎么讲？

如果 DAU 一亿，大促峰值下单 QPS 可能远高于日均。

要估算下单一次会访问订单库、库存库、价格服务、优惠服务和 MQ，并分别计算容量和冗余。

## 共性一致性模型

状态机、Outbox、幂等、重试、对账和补偿的统一闭环及 Java 17 示例见
[共享模型：最终一致、状态机和补偿](../shared-answer-models.md#最终一致状态机和补偿)。

## 专家级完整回答

```text
容量估算要从业务流量倒推系统资源。先估算 DAU、峰值系数和核心接口 QPS，再拆解每个接口的数据库、缓存、
MQ、下游调用和机器资源消耗，最后加上冗余、故障切换和发布容量。

估算必须用压测验证，并通过线上指标持续校准，不能只停留在纸面计算。
```

## 回答评分点

高分答案应该覆盖：

- 从业务目标倒推技术容量。
- 日均流量不能代表峰值。
- 要拆解到数据库、缓存、MQ 和下游。
- 要考虑冗余和故障场景。
- 压测和监控用于校准。
