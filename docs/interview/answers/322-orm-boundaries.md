# 322 ORM 能解决哪些问题，不能解决哪些问题？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

ORM 解决的是对象和关系表之间的映射、基础 CRUD、参数绑定、结果集封装和部分 SQL 复用问题。

ORM 不能替代数据库设计、索引设计、事务设计、慢 SQL 分析、分库分表设计和复杂业务查询建模。
在高并发电商系统中，ORM 是提高开发效率的工具，不是屏蔽数据库复杂度的银弹。

## ORM 能解决的问题

主要包括：

- 实体和表字段映射。
- 基础新增、查询、更新、删除。
- 参数绑定，降低 SQL 注入风险。
- 分页和条件构造。
- 统一审计字段填充。
- 类型转换。
- 代码重复减少。

这些能力能让常规业务代码更稳定。

## ORM 不能解决的问题

不能解决：

- 表结构是否合理。
- 索引是否命中。
- SQL 是否产生回表。
- 事务边界是否正确。
- 锁竞争是否严重。
- 分库分表路由是否合理。
- 大查询是否拖垮数据库。
- 业务一致性如何保证。

复杂系统里，开发者仍然要懂数据库。

## 常见误区

误区包括：

- 认为 ORM 生成的 SQL 一定高效。
- 过度使用动态条件导致 SQL 不可控。
- 对热点接口不看实际 SQL。
- 把复杂聚合查询塞进 ORM。
- 忽视事务传播和连接占用。

高并发场景要看最终落到数据库的 SQL。

## 在 eMall 项目中怎么讲？

eMall 中用户、地址、基础配置等简单表适合使用 MyBatis Plus 提升效率。

订单列表、库存扣减、对账扫描、Outbox 扫描这类关键路径要明确 SQL、索引和事务边界。
这些场景可以使用 Mapper，但不能让 ORM 自动生成不可控查询。
