# 587 你为什么不使用全局分布式事务？

[返回按分类学习面试题](../README.md)

## 核心判断

全局事务把多个服务的可用性、延迟和锁持有时间绑定在一起。在高并发交易链路中，一个慢参与者或协调器故障就可能放大连接占用和锁竞争，因此本项目优先缩小强一致边界，而不是把数据库事务跨服务延伸。

## 取舍依据

- 聚合内部用本地 ACID、唯一约束和条件更新保证不可破坏的不变量。
- 跨服务用状态机、Outbox、幂等消费、补偿和对账实现可恢复的最终一致。
- 对用户承诺必须明确：处理中状态、超时关闭和退款都要可见、可查询、可重放。
- 极少数确需资源预留的流程可以局部采用 Saga 或 TCC，但不能把它当默认基础设施。

## 项目证据与边界

订单、库存和支付各自拥有数据，不共享跨库事务。该选择牺牲了“提交瞬间所有服务一致”，换取故障隔离与可恢复性；前提是事件延迟、补偿失败和对账差异都有指标、告警和人工兜底。
