# 333 缓存穿透是什么？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

缓存穿透是指请求查询一个缓存和数据库都不存在的数据，导致每次请求都绕过缓存打到数据库。
如果攻击者大量请求不存在的商品 ID 或用户 ID，数据库会被无效流量压垮。

常见治理是缓存空值、使用布隆过滤器、参数校验和风控限流。

## 产生原因

原因包括：

- 查询不存在的 key。
- 缓存不保存空结果。
- 外部恶意枚举 ID。
- 参数校验不严格。
- 历史数据被删除但请求仍然存在。

穿透的特点是缓存命中率很低，数据库 QPS 异常升高。

## 治理方式

方式：

- 缓存空值并设置较短 TTL。
- 使用布隆过滤器拦截不存在 key。
- 对非法参数直接拒绝。
- 对枚举行为做限流和风控。
- 热点不存在 key 做单独保护。

空值缓存要设置短 TTL，避免删除后重建数据不可见太久。

## 布隆过滤器的作用

布隆过滤器可以快速判断某个 key 是否可能存在。

如果布隆过滤器判断一定不存在，就不访问缓存和数据库。如果判断可能存在，再访问缓存和数据库。
它有误判率，但不会漏判已加入的数据。

## 电商系统实践

商品详情接口如果收到大量不存在的 `skuId`，不能每次都查数据库。

大型电商系统可以在商品上架时把 `skuId` 加入布隆过滤器。查询不存在商品时缓存空对象，例如
`product:detail:123 = EMPTY`，TTL 设置为几分钟，并配合风控限制异常来源。
