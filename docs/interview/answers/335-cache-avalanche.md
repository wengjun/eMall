# 335 缓存雪崩是什么？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

缓存雪崩是大量缓存 key 在同一时间失效，或者 Redis 整体不可用，导致请求大规模回源数据库，
进而拖垮数据库和上游服务。

治理要从 TTL 随机化、缓存预热、限流降级、熔断、Redis 高可用和数据库保护几层一起做。

## 产生场景

场景包括：

- 批量 key 使用相同 TTL。
- 大促开始前缓存集中失效。
- Redis 集群故障。
- 缓存预热失败。
- 发布后缓存 key 版本整体切换。

雪崩是系统性失效，不是单个 key 问题。

## 治理方式

方式：

- TTL 加随机抖动。
- 热点数据提前预热。
- 分批刷新缓存。
- Redis 主从或 Cluster 高可用。
- 回源限流。
- 数据库熔断保护。
- 降级返回默认值或旧值。

重点是不要让所有流量同时打到数据库。

## 和击穿的区别

区别：

- 击穿通常是单个热点 key。
- 雪崩是大量 key 或整个缓存层。
- 击穿关注热点重建。
- 雪崩关注系统级保护。

雪崩影响范围更大。

## 在 eMall 项目中怎么讲？

eMall 首页、类目页和商品详情页如果统一设置 30 分钟 TTL，可能在整点集中失效。

应对方式是 TTL 加随机值，例如 30 分钟加 0 到 5 分钟随机抖动，并在大促前预热核心商品和活动
配置。Redis 故障时，网关和服务端要限流，非核心展示可降级。
