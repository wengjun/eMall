# 680 故障检测为什么不可靠，脑裂如何形成？

[返回按分类学习面试题](../README.md)

## 超时只能产生怀疑

在异步网络中，观察者无法仅凭“暂时没有响应”区分以下情况：节点崩溃、网络分区、丢包、进程长暂停、CPU 饥饿、磁盘卡顿或响应仍在路上。因此故障检测器输出的是 suspect，而不是物理事实。

心跳间隔短、超时小，切换快但误判多；阈值大，误判少但恢复时间长。Phi Accrual 一类检测器根据历史到达间隔输出连续怀疑度，也只能改善决策，不能消除不确定性。

## 脑裂是怎样形成的

```text
        网络分区
节点 A  X------X  节点 B
  |                 |
客户端组 1        客户端组 2
```

A 与 B 都看不到对方，如果规则是“看不到旧主就自升为主”，两边会同时接受写入。网络恢复后，不可合并的库存扣减、支付和唯一编号已经产生冲突。

## 安全设计的四道防线

1. **多数派授权**：只有能联系配置多数派的一侧可以选主和提交，少数派停止写。
2. **任期单调**：每次领导权使用更大的 epoch/term，旧任期消息不能被当作当前写入。
3. **资源 fencing**：数据库、存储或下游拒绝旧 term，即使旧主恢复执行也写不进去。
4. **人工与自动化边界**：网络状态不明时禁止运维强制双边提升；灾难切换要记录数据丢失点和恢复步骤。

STONITH 可以直接隔离旧主的电源或网络，适用于共享存储等无法验证 fencing token 的场景；仅发送“请停止”RPC 不算隔离，因为失联节点恰好收不到。

## 监控和演练

不能只监控“当前有几个 Leader”，还应观察：成员视图是否一致、Quorum 是否可达、term 是否异常增长、复制提交位点差距、旧 term 写入拒绝次数以及客户端是否仍连接旧主。

故障演练至少覆盖单向分区、双向分区、Leader 长 GC、磁盘停顿、时钟跳变、节点重启后旧请求重放。验收条件不是“服务最终恢复”，而是整个过程中业务不变量没有被破坏。

在 eMall 中，订单数据库主从切换和定时任务 Leader 都必须把“检测故障”与“授予新写权限”分开。健康检查触发切换只是活性机制，多数派、任期和 fencing 才提供安全性。
