# 372 事件应该携带全量数据还是只携带 ID？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

事件携带全量数据还是只携带 ID，要看事件用途、一致性要求、消息大小、消费者自治能力和数据隐私。
全量数据能降低消费者回查依赖，只携带 ID 能减小消息并避免敏感数据扩散。

生产中常用折中方案：事件携带关键业务快照和 ID，不携带过大的明细或敏感字段。

## 只携带 ID

优点：

- 消息小。
- schema 简单。
- 敏感数据扩散少。
- 数据以源服务最新状态为准。

缺点：

- 消费者需要回查源服务。
- 源服务压力增加。
- 回查可能读到事件之后的新状态。
- 源服务故障会影响消费。

## 携带全量数据

优点：

- 消费者自治。
- 减少回查。
- 保留事件发生时快照。
- 适合构建读模型。

缺点：

- 消息变大。
- schema 演进复杂。
- 敏感数据风险增加。
- 重复存储成本高。

全量也不应该无限制携带大字段。

## 推荐折中

推荐携带：

- 事件 ID。
- 聚合根 ID。
- 事件类型。
- 发生时间。
- 版本号。
- 关键业务字段快照。
- 追踪 ID。

大文本、图片、长列表和敏感字段尽量不放。

## 在 eMall 项目中怎么讲？

eMall 的订单创建事件可以携带 `orderId`、`userId`、金额、订单状态、商品行摘要和事件版本。

不要把完整商品描述、用户隐私信息和大促复杂规则全部塞进消息。履约和搜索等消费者能基于快照
处理，必要时再按 ID 回查。
