# 196 如何设计订单、库存、支付的边界？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

订单服务负责交易状态和订单生命周期，库存服务负责库存数量、预占和释放，支付服务负责支付单、渠道交互和支付状态。
三者通过 API 和事件协作，不能互相直接写表。

订单是交易编排中心，但不应该拥有库存和支付的内部数据。

## 订单服务边界

订单服务负责：

- 创建订单。
- 维护订单状态机。
- 记录订单明细。
- 管理取消、超时、完成。
- 处理支付结果对订单状态的影响。
- 发布订单领域事件。

订单服务不直接扣库存余额，也不直接调用第三方支付渠道。

## 库存服务边界

库存服务负责：

- 可售库存。
- 库存预占。
- 库存释放。
- 库存扣减确认。
- 仓库和 SKU 库存规则。
- 库存流水。

它对外提供预占、确认、释放等能力。

## 支付服务边界

支付服务负责：

- 创建支付单。
- 调用支付渠道。
- 处理支付回调。
- 维护支付状态。
- 支付幂等。
- 支付对账。

支付服务发布支付成功或失败事件，订单服务据此更新订单状态。

## 电商系统实践

下单流程可以是：

```text
订单服务创建待确认订单
-> 调用库存服务预占库存
-> 创建待支付订单
-> 支付服务创建支付单
-> 支付成功事件
-> 订单服务更新为已支付
-> 库存服务确认扣减
```

失败时通过状态机和补偿任务恢复。
