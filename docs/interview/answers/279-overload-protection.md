# 279 如何做过载保护？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

过载保护是在系统资源接近极限时主动限流、拒绝、降级或减少工作量，避免系统彻底崩溃。
它要基于 CPU、线程池、队列、连接池、延迟、错误率和业务成功率等指标触发。

过载保护的原则是有序拒绝一部分请求，保住核心请求。

## 触发指标

指标包括：

- CPU 持续过高。
- GC 暂停增加。
- 线程池队列过长。
- 连接池耗尽。
- P99 延迟升高。
- 错误率升高。
- MQ 积压快速增长。
- 数据库慢查询增多。

单一指标可能误判，最好多指标组合。

## 保护动作

动作包括：

- 入口限流。
- 并发限制。
- 快速失败。
- 关闭非核心功能。
- 降级返回缓存。
- 降低后台任务速度。
- 暂停低优先级流量。
- 熔断故障下游。

动作要按服务分级和业务优先级执行。

## 设计原则

原则：

- 尽早拒绝。
- 有界队列。
- 核心优先。
- 非核心可降级。
- 避免无限重试。
- 保护下游。

过载时排队越长，恢复越慢。

## 电商系统实践

大促时订单服务检测到线程池队列和 P99 延迟持续升高，应降低秒杀队列消费速度，关闭推荐和营销非核心调用。

普通下单和支付确认要优先保住。
