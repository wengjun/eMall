# 522 设计优惠券系统

[返回按分类学习面试题](../README.md)

## 题目

设计优惠券系统。

## 先给面试官的短答案

优惠券系统要支持发券、领券、用券、锁券、核销、退券和风控。核心难点是规则复杂、并发领券、下单锁定、
支付后核销、取消后释放，以及金额计算可解释。用券不能只在前端计算，必须由后端价格或促销服务统一校验。

## 核心模型

优惠券通常包括券模板、用户券、使用规则、适用范围、有效期、预算、库存、核销记录和退券记录。

券模板定义规则，用户券表示某个用户拥有的券，核销记录用于审计和退款。

## 发券和领券

发券可以是系统发放、活动领取、商家发放或补偿发放。领券要控制库存、每人限领、活动时间、用户资格和防刷。

高并发领券可以用 Redis 扣减券库存，再异步落库。数据库仍要有唯一约束防止同一用户重复领取。

## 用券和锁券

下单前要根据商品、商家、类目、金额、时间、用户等级和叠加规则计算可用券。用户选择优惠券后，订单创建时先锁券。

支付成功后核销，订单取消或支付超时后释放。锁券、核销和释放都要幂等，避免重复核销或重复释放。

## 金额正确性

优惠券会影响订单金额、支付金额、退款金额和商家结算。每次计算要保存优惠明细快照，便于售后退款和对账。

规则引擎要可解释，不能只输出最终金额。面试时要强调“金额可追溯”。

## 在 eMall 项目中怎么讲？

eMall 的 `promotion` 和 `pricing` 模块可以共同处理优惠券。`promotion` 管券和规则，`pricing` 汇总价格计算，
`order` 保存优惠快照，`after-sales` 按快照退款。

## 专家级完整回答

```text
优惠券系统要同时解决营销灵活性和交易正确性。

我会把券模板、用户券、锁券记录、核销记录和退券记录建模清楚。领券阶段控制库存和防刷；
下单阶段锁券；支付成功后核销；取消或超时后释放。

金额计算要保存明细快照，保证订单、支付、退款和结算都能解释。优惠券不是简单减金额，
而是贯穿交易、售后和财务的规则系统。
```

## 回答评分点

高分答案应该覆盖：

- 覆盖发券、领券、锁券、核销、释放和退券。
- 能说明券模板、用户券、规则和核销记录。
- 知道高并发领券要防重复和防刷。
- 强调金额计算和优惠快照可解释。
- 能结合订单、支付、售后和结算说明。
