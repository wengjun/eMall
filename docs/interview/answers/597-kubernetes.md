# 597 你为什么要引入 Kubernetes？

[返回按分类学习面试题](../README.md)

## 核心判断

当服务数量、实例数量和发布频率足够高时，Kubernetes 统一调度、服务发现、滚动发布、弹性和故障重建的收益超过平台复杂度。它提供编排原语，但不会自动让应用高可用。

## 取舍依据

- 应用必须先正确实现 readiness、liveness、优雅停机和无状态化，平台才能安全迁移实例。
- requests、limits、HPA、PDB 和拓扑分布需要按容量数据配置，默认值不能代表生产方案。
- 配置、Secret、网络策略、镜像供应链和 RBAC 都进入新的安全边界。
- 少量稳定服务部署在虚拟机或托管平台可能更便宜、更容易运维。

## 验证证据与边界

Helm Chart、探针、滚动发布和多可用区部署定义只能表达生产约束，不能证明集群已经达到目标容量。
仍需在真实基础设施上完成负载、故障和升级演练。
