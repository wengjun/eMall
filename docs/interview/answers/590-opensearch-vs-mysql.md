# 590 你为什么用 OpenSearch，而不是 MySQL like 查询？

[返回按分类学习面试题](../README.md)

## 核心判断

电商搜索需要分词、相关性排序、同义词、聚合筛选和大结果集检索，前缀或包含式 `LIKE` 难以稳定使用 B+Tree 索引，也无法表达完整的检索模型。MySQL 仍负责商品事实，OpenSearch 是可重建的搜索读模型。

## 取舍依据

- 精确主键、唯一键和少量结构化过滤优先 MySQL；全文检索和相关性排序交给搜索引擎。
- 商品变更通过事件同步，必须监控延迟、失败和版本，防止旧事件覆盖新文档。
- 索引映射、分片数和深分页需要容量设计，不能把 OpenSearch 当无限扩展的数据库。
- 搜索索引允许最终一致，但下单时必须回源校验上下架、价格和库存。

## 项目证据与边界

eMall 把搜索索引设计为可全量重建的派生数据，并保留降级路径。引入 OpenSearch 增加了集群、同步和一致性成本；若业务只有精确查询，不应使用它。
