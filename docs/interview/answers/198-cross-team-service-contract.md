# 198 如何处理跨团队服务契约？

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

跨团队服务契约要文档化、版本化、自动化测试，并建立变更评审和兼容性规则。
服务提供方不能随意改字段、错误码和语义；消费方也不能依赖未承诺的内部细节。

契约治理的目标是让团队可以独立演进，而不是靠口头同步。

## 契约内容

应包含：

- API 或事件 schema。
- 字段语义和类型。
- 必填和可选规则。
- 错误码。
- 幂等和重试规则。
- 超时和限流约定。
- 版本和废弃策略。
- SLA 和责任边界。

契约不只是接口路径，还包括行为语义。

## 变更规则

规则包括：

- 新增可选字段通常兼容。
- 删除字段是破坏性变更。
- 改字段类型是破坏性变更。
- 改错误码语义是破坏性变更。
- 新增必填参数要走新版本。
- 废弃要提前公告和监控。

这些规则要进入 CI/CD 门禁。

## 协作机制

需要：

- OpenAPI 或 Protobuf 仓库。
- 契约测试。
- 消费者驱动契约。
- 变更评审。
- 兼容性扫描。
- 调用方使用监控。

没有自动化，跨团队契约会随着人员变化失控。

## 在 eMall 项目中怎么讲？

商家开放 API 由开放平台团队维护契约，订单团队提供内部订单能力。

如果订单字段变更，不能直接影响商家 API；开放平台需要做稳定映射，并通过契约测试保护外部兼容。
