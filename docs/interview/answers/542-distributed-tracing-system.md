# 542 设计链路追踪系统。

[返回按分类学习面试题](../README.md)

## 先给面试官的短答案

链路追踪系统要可靠传播 Trace Context，以低开销采集 Span，通过分区队列削峰，再按服务、时间和 Trace ID
建立可检索存储。核心取舍是采样精度、查询时延、保留周期与成本，追踪系统故障不能阻塞交易请求。

## 核心拆解

- SDK 在进程内生成 Span 并异步批量上报，入口创建 Trace ID，跨 HTTP、Dubbo 和 Kafka 继续传播上下文。
- Collector 做鉴权、租户隔离、清洗和路由，Kafka 缓冲突发流量，写入可按时间分区的 Trace 存储。
- 同时支持头部采样和尾部采样，错误、慢请求及关键交易优先保留，正常流量按策略降采样。
- 监控丢弃率、摄取延迟、查询 P99 和单位 Span 成本；队列满时丢弃观测数据而不是反压交易链路。

## 深度完善：系统设计高分展开

围绕「设计链路追踪系统。」，系统设计题要按目标、规模、架构、数据、失败路径、演进六层展开。
不要只画组件图，必须讲清每个组件为什么存在，以及它如何在大促和故障场景下保持可控。
